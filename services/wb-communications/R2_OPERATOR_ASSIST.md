# R2 — помощь оператору: черновик 3.1E в карточке Telegram

Статус: код в `main` после слияния; **включается только отдельным ACK владельца**.

## Что видит оператор

Карточка: черновик V2 («✍️ Проект ответа»), под ним «✨ Вариант 3.1E». Кнопки: «✅ Опубликовать» (V2),
«✨ Опубликовать 3.1E», «✏️ Изменить», «🔄 Перегенерировать», «⏭ Пропустить». Публикует только человек.

**Кнопка публикации 3.1E есть, только если весь точный текст 3.1E виден в этом же сообщении.** Если
карточку обрезал лимит Telegram (длинный отзыв, длинные достоинства/недостатки, длинные черновики), вместо
неё стоит «✨ Показать 3.1E полностью»: отдельное сообщение с полным текстом 3.1E и одной кнопкой
«✨ Опубликовать 3.1E», привязанной к той же версии карточки. После перегенерации или правки она устаревает.

## Какое правило проверяет публикацию

| Действие | Правило |
|---|---|
| «✅ Опубликовать» (черновик V2) | production-совместимое `LIVE_V2` — как сейчас в production |
| «✏️ Изменить» → «✅ Опубликовать» (ручная правка) | `LIVE_V2` |
| «✨ Опубликовать 3.1E» | политика v3.1E — **дважды**: до принятия черновика и в публикаторе перед записью в WB |

Правило выбирается действием, а не флагом R2: включение R2 не меняет, какой ответ V2 можно опубликовать.
`V31_ENFORCE_LIVE_PUBLICATION_POLICY` в первом выпуске R2 **выключен**.

Нажатие «✨ Опубликовать 3.1E»: шлюз публикации → текущая политика v3.1E на точном сохранённом тексте.
При BLOCK или ошибке проверки черновик **не принимается**: ответ, версия карточки, статус и WB не
меняются, оператор получает «Вариант 3.1E сейчас не проходит правила публикации…». Иначе черновик
атомарно принимается как следующая версия ответа, и обычный проверенный публикатор проверяет политику
ещё раз, пишет в WB один раз и подтверждает обратным чтением.

## Переменные (аддитивно, без `--env-vars-file`)

| Переменная | R2 |
|---|---|
| `V31_OPERATOR_DRAFT_ENABLED` | `true` |
| `V31_ENFORCE_LIVE_PUBLICATION_POLICY` | `false` / не задавать — V2 остаётся на `LIVE_V2` |
| `V31_OPERATOR_DRAFT_BUDGET_SECONDS` | не задавать (100) |
| `V31_QUALITY_SHADOW_ENABLED` и прочие `V31_SHADOW_*` | **удалить** (R1 при R2 всё равно не запускается); когорта R1 в `v31_shadow_pilot` остаётся историей, не удалять |
| `V31_OPERATOR_RECOVERY_ENABLED`, `V31_OWNER_OVERRIDE_ENABLED` | не задавать |

## Выкладка

1. Образ из merge SHA (Cloud Build, `deploy/cloudbuild.publication.yaml`), digest.
2. Ревизия без трафика с переменными R2 (`--no-traffic --tag`), `/health`, старт без ошибок,
   окружение = текущее production без `V31_SHADOW_*` + `V31_OPERATOR_DRAFT_ENABLED=true`.
3. Атомарное переключение 100% трафика между ежечасными опросами. `/poll` вручную не вызывать.
4. На первом новом отзыве: карточка с двумя вариантами; публикация 3.1E проходит через проверку и
   обратное чтение WB.

## Откат

Трафик на последнюю ревизию без R2 (сейчас `evetis-wb-communications-tags-4e63608`, production-правило,
R1 выключен): `gcloud run services update-traffic evetis-wb-communications --region europe-west1
--to-revisions evetis-wb-communications-tags-4e63608=100`. Старые карточки с кнопкой 3.1E после отката
отвечают «Вариант 3.1E сейчас отключён» и ничего не публикуют.

## Стоимость

Один дополнительный вызов модели на новую коммуникацию (gpt-5.6-terra, ~2 с).

## R2.1 — 3.1E основной черновик (`V31_PRIMARY_OPERATOR_ENABLED`)

Включается отдельным ACK владельца, по умолчанию выключен. При `false` всё описанное выше (R2) без изменений.

Карточка ведёт с «✨ Рекомендуемый ответ 3.1E» и обычными кнопками. «✅ Опубликовать» публикует его по
политике v3.1E. Правка такого ответа остаётся на политике v3.1E. Старый V2 — только «🗂 Старый вариант V2»;
«↩️ Использовать вариант V2» явно делает его ответом (политика `LIVE_V2`). Если 3.1E технически не
получился, карточка показывает «Резервный ответ V2» с причиной.

| Случай | Что видит оператор | Публикация |
|---|---|---|
| обычный отзыв/вопрос | «✨ Рекомендуемый ответ 3.1E» | «✅», политика v3.1E |
| умеренный дискомфорт (аромат → тошнота, головокружение, головная боль) | «⚠️ Требует внимания оператора» + осторожный ответ | «✅» вручную, политика v3.1E |
| реакция кожи (шаблон S1/S2) | «⚠️ Требует внимания оператора» + утверждённый шаблон | «✅» вручную |
| серьёзная безопасность (дыхание, отёк, обморок, скорая, глаза, проглатывание, рвота, ожог/пузыри, ребёнок) | «⛔ Нужна проверка человеком», ответа нет | только свой текст через «✏️ Изменить»; политика v3.1E `v31_human_safety` (снят только `V-SAFETY-ROUTE`) |
| сбой 3.1E | «Резервный ответ V2» | «✅», `LIVE_V2` |

Переменные для включения (аддитивно): `V31_PRIMARY_OPERATOR_ENABLED=true`; `V31_OPERATOR_DRAFT_ENABLED`
можно оставить; `V31_ENFORCE_LIVE_PUBLICATION_POLICY`, override, recovery не задавать.

Откат без отката кода: трафик на ревизию без флага (или новая ревизия с `V31_PRIMARY_OPERATOR_ENABLED=false`).
Уже отправленные карточки R2.1 продолжают работать: политика берётся из истории версий ответа.

## R2.2 — только 3.1E (`V31_ONLY_OPERATOR_ENABLED`)

Включается отдельным ACK владельца, по умолчанию выключен (тогда работает R2.1). Включает и R2.1.

| Случай | Карточка | Кнопки | Политика |
|---|---|---|---|
| обычный ответ 3.1E | «✨ Рекомендуемый ответ 3.1E» | ✅ ✏️ 🔄 ⏭ | v3.1E |
| вопрос только о поступлении | честный ответ без даты (SAFE_INFORMATION_GAP) | ✅ ✏️ 🔄 ⏭ | v3.1E |
| умеренный дискомфорт | ⚠️ + осторожный ответ | ✅ ✏️ 🔄 ⏭ | v3.1E |
| серьёзная безопасность | ⛔, ответа нет | ✏️ Написать вручную, ⏭ | `v31_human_safety` |
| юр./подлинность/нераспознанный вопрос/возврат | ⛔ с причиной, ответа нет | ✏️ Написать вручную, ⏭ | v3.1E |
| технический сбой 3.1E | ⚠️ «Не удалось подготовить ответ 3.1E» | 🔄 Повторить, ✏️, ⏭ | v3.1E |

V2 в карточке не появляется и не публикуется: хранится в `ai_answer` только для диагностики и отката.
Включение (аддитивно): `V31_ONLY_OPERATOR_ENABLED=true`. Откат: трафик на ревизию R2.1
(`V31_PRIMARY_OPERATOR_ENABLED=true` без этого флага). Карточки R2.2 после отката продолжают публиковать
только 3.1E/текст оператора.
