# Security audit events — contract `wbcomm.security.v1` (D-19b / F-18)

Why. `evetis-wb-communications` is publicly invocable (`allUsers` → `run.invoker`) because
Telegram must reach the webhook. Cloud Run IAM therefore cannot say who caused a write. These
events let the trusted audit (`tools/autonomy`, F-18 semantics) prove, per request, that every
external mutation happened only after application-level authentication.

Producer: `app/utils/audit_events.py`. One JSON line on stdout per event (Cloud Logging
`run.googleapis.com/stdout`), independent of the `logging` level and handlers.

## Correlation chain

```
run.googleapis.com/requests   trace = projects/P/traces/T            (platform, immutable)
  request_start               trace_id = T, correlation_id = C        (one per request)
  auth_ok | auth_denied       T, C, auth_mechanism, principal_class
  authz_ok | authz_denied     T, C  (Telegram allow-list, allowlist_configured)
  mutation_attempt            T, C, mutation_id = M, auth_event_id = id of the auth_ok above
  mutation_success | mutation_failure   T, C, M, result
  request_done                T, C, status_code, result = ok|denied|none, mutation_attempts = n
```

`T` comes from Cloud Run's `X-Cloud-Trace-Context` (or W3C `traceparent`) and is written to
`logging.googleapis.com/trace`, so Cloud Logging puts the event on the same trace as the
platform request log. `C` is generated by the service for each request (uuid4 hex).

## Fields (closed set)

| field | values |
|---|---|
| `security_schema` | `wbcomm.security.v1` |
| `event_type` | `request_start`, `request_done`, `auth_ok`, `auth_denied`, `authz_ok`, `authz_denied`, `mutation_attempt`, `mutation_success`, `mutation_failure` |
| `event_id`, `correlation_id`, `mutation_id` | 32 hex |
| `trace_id` / `span_id` | 32 hex / 16 hex, or null if the request had no trace |
| `ts` | RFC 3339 UTC, microseconds |
| `service`, `revision` | `K_SERVICE`, `K_REVISION` |
| `route` | one of `/poll`, `/telegram-webhook`, `/health`, `/admin/test-*`, else `other` |
| `method` | HTTP method or `other` |
| `auth_mechanism` → `principal_class` | `scheduler_secret` → `cloud_scheduler`; `telegram_webhook_secret` → `telegram_bot_api`; `admin_token` → `admin_operator`; `telegram_allowlist` → `telegram_user` |
| `result` | auth: `ok`/`denied`; mutation: `attempt`, `success`, `rejected`, `error`, `outcome_unknown`; request_done: `ok`/`denied`/`none` |
| `reason` | `missing`, `mismatch`, `not_configured` (auth_denied only) |
| `mutation_class` | `wb_feedback_answer`, `wb_question_answer`, `tg_send_message`, `tg_edit_message`, `tg_answer_callback`, `tg_set_webhook`, `tg_other` |
| `target_system` / `target_ref` | `wb` → `wb:<WB id>` (public object id); `telegram` → `tg_chat:<sha256[:16]>` / `tg_callback:<…>` / `tg:bot` |
| `error_class` | exception class name only |
| `status_code`, `mutation_attempts`, `duration_ms` | integers |
| `allowlist_configured` | true only if BOTH chat and user allow-lists are non-empty |

Never emitted: request/response headers, secrets or tokens, message or answer text, buyer data,
raw chat/user/callback ids. Every string value must match `^[A-Za-z0-9_.:/@+=-]{0,160}$`
after redaction; otherwise it is replaced by `<invalid>`, which the audit treats as a failure.

## Outcome classification

| write | success | rejected | error (provably not sent) | outcome_unknown |
|---|---|---|---|---|
| WB answer / question answer | 2xx (no in-band `error: true`) | 4xx, in-band `error: true` | 429 after retries | 5xx, read timeout / transport after send, anything unexpected |
| Telegram Bot API | `ok: true` | `ok: false` | `ConnectError`, `ConnectTimeout` | other transport errors, non-JSON response |

## What the audit derives (not the service)

For each platform request log of the service in the audit window: exactly one `request_start`
and `request_done` on the same trace with one `correlation_id`; every `mutation_attempt`
preceded by `auth_ok` of the same request (`auth_event_id`); exactly one outcome per attempt,
none `outcome_unknown`; `request_done.mutation_attempts` equal to the attempts seen; no event
without a platform request; no duplicated trace. Anything else is BLOCKED, never PASS.
