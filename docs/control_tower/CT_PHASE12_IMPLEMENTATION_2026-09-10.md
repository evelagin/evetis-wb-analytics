## 2. Витрины — узкие правки (repo == production, md5 сверен по шести витринам)

| Витрина | Правка | Зачем |
|---|---|---|
| `V_CT_ACTION_QUEUE` | `what_to_do` больше не режется до 110 символов (перенос строк в Metabase); новые `why_owner` (одна фраза без перечня SKU; для строк правил — из шаблона по `reason_code`: `FF_SHELF_EMPTY`, `*_STOCKOUT_WEEK1`, `BUNDLE_PLAN_WEEK1`, `DRR_ABOVE_CEILING_7D` → «ДРР 7 дн. 37 % при потолке 24 % — перерасход ≈ 353 ₽ за неделю», `OVERSTOCK_365D` → «запас 3885 фл. = 1228 дн. плана — к 31.03.2027 останется ≈ 2829 фл. (срок годности 22.10.2027)»), `sku_breakdown` (перечень SKU из seed-строк «Снять с паллет / Отгрузить …» — только для Деталей), `effect_kind_ru` + `effect_line`; гуманизация кодов; `why_short` сохранён = полный текст (совместимость) | §4 и §5 ТЗ: без «…», «зачем» одной фразой, тип эффекта |
| `V_CT_OWNER_HOME` | CTE `prev`: позавчера (`*_dby`) и тот же день недели неделю назад (`*_lw`) — позиции, физ. ед., выручка, вклад, ДРР; `dby_date`, `lw_date`; `forecast_line` — «проданных позиций» | §6: контекст KPI «vs предыдущий сопоставимый период» |
| `V_CT_SKU_CONTROL` | `status_ru`, `channel_ru`, `kind_ru` (обёртка над прежним SELECT; расчёты не тронуты) | §8 статусы |
| `V_CT_DAILY_BRIEF_LINES` | разделы «Вчера / План месяца / Главные отклонения / Сегодня сделать / Решения владельца / Данные»; строки с `effect_line` и `why_owner`; «Вчера» дополнено «позавчера N поз., неделю назад M поз.»; «Надёжность прогноза: LOW (низкая) — …» | §9 сводка |
| `V_CT_ATTENTION`, `V_CT_ACTION_CANDIDATES` | «карточек» → «поз. / проданных позиций» в заголовках сигналов и текстах правил | §1 подписи |

Типы финансового эффекта (`effect_kind_ru`), по `reason_code` / `action_type`:
`EXPIRY*`/`LIQUIDATION` → «Предотвращённый риск списания» (+) / «Риск списания» (−); `ADS_REVIEW`/`DRR*` → «Ожидаемый вклад» (+) / «Перерасход рекламы» (−);
`ACCELERATE`/`OVERSTOCK*` → «Потенциальный cash effect»; `DECISION` с отрицательной суммой → «Стоимость решения»; прочее с минусом → «Выручка под риском»; иначе — «Потенциальная выручка».
Сумма без типа на владельческих экранах не встречается (T34); при `NULL` показывается «—».

## 4. Sales Plan (дашборд 6)

Фильтры сверху (static-list, человеческие значения): **Период** = Сегодня | 7 дней | Текущий месяц (по умолчанию) | Сезон;
**Канал** = Все (пусто) | WB | Ozon (в SQL `UPPER({{marketplace}})`); вторичные — Товар/набор, Линия, SKU.
Кнопок в Metabase нет; static-list — простейший нативный выбор без ввода текста.

```
Продажи за период · по каналам (Все / WB / Ozon): период · план продаж · факт по плану · выполнение · продано всего · физ. ед. · выручка · вклад · статус
A · Текущий месяц · план продаж и факт по неделям (bar) + План месяца (таблица)
B · Топ-12 SKU текущего месяца (таблица: план, факт, выполнение, прогноз, план месяца, запаса дней, статус, почему)
C · Каналы · WB и Ozon · текущий месяц (bar + таблица)
D · Сезон 09.09.2026 – 31.03.2027 · нарастающим итогом (линия + итоги)
E · SKU × канал · таблица контроля (топ-20; 9 колонок: SKU · Канал · План продаж · Факт продаж · Выполнение плана · Прогноз месяца · Запаса дней · Статус · Почему)
```
Период действует на блок «Продажи за период» (план и «факт по плану» — только плановые дни с 09.09; «продано всего» — все дни периода;
«Сегодня» помечен «день не закрыт»); канал — на все блоки. Проверено API: 7 дней → 03.09–09.09, Сезон → с 09.09, Ozon → 1 строка.
Диаграмма-row топ-12 и «WB и Ozon · сезон» перенесены в Детали.

## 11. Остающиеся ограничения UX

- Заголовки колонок Metabase не переносятся и не имеют tooltip — при 9–10 колонках единицы вынесены в название карточки, а не в заголовок.
- Trend-карточки показывают префикс Metabase «сравнение:» и проценты с двумя знаками (44.3 %) — не настраивается.
- Нет кнопок-переключателей периода: фильтр-список сверху дашборда (значения фиксированы, ввод не нужен).
- «Сегодня» в блоке периода — неполный день (WB отдаёт продажи с задержкой); помечено в подписи.
- Кнопки «Готово / Начать» пусты, пока владелец не задеплоил web-app и не заполнил `CT_CONFIG.action_webapp_url` (шаг Phase 1.1).
- Автообновление ждёт `terraform apply` через workflow `infra` (шаг Phase 1.1); пока обновление — вручную `CALL sp_ct_refresh_daily()`.
- Скриншоты в репозиторий не сохранялись (встроенный браузер отдаёт изображение только в чат); метрики `ctQA` — в §6.
