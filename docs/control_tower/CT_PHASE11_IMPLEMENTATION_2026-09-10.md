## 3. Уверенность прогноза

Явные, тестируемые правила (`V_CT_OWNER_HOME`, тест T27):

| Шаг | Правило |
|---|---|
| База | закрытых плановых дней 0–2 → **LOW**, 3–9 → **MEDIUM**, ≥ 10 → **HIGH** |
| −1 ступень | данные за вчера неполные (WB или Ozon не закрыли день) |
| −1 ступень | риск наличия: ≥ 10 % плана ближайших 14 дней приходится на SKU без недельного покрытия на площадке |

## 4. Рабочий процесс владельца по действиям

**Рассмотренные варианты.** (a) Metabase Actions — не поддерживают BigQuery; (b) Google Sheet как
внешняя таблица BigQuery — двусторонняя синхронизация, Drive-scope у SA, не «один клик»; (c) Cloud Run
сервис — новый образ, IAM, apply; (d) Apps Script web-app — существующий инструмент проекта
(`apps-script/`, advanced service BigQuery и scope уже в манифесте), auth = Google-аккаунт владельца,
ни ключей, ни серверов. **Выбран (d).**

`apps-script/CtOwnerActions.gs`: `doGet(id, status[, note])` → валидация (`^CT-\d{4}$`, белый список
статусов) → **единственный разрешённый путь записи** `CALL evetis_ref.sp_ct_action_update(@id, @status,
@note, 'owner:webapp')` через `BigQuery.Jobs.query` с параметрами → страница подтверждения с карточкой
действия, кнопками других статусов, полем заметки и undo (`→ OPEN`). Ссылки в Metabase строятся
витриной `V_CT_ACTION_QUEUE` из `CT_CONFIG.action_webapp_url` (`?id=CT-0002&status=DONE`) и открываются
в новой вкладке. Пока ключ пуст — колонки «Готово / В работе» пустые, ничего не ломается.

**Проверено в BigQuery (тем же CALL, что делает web-app):** `CT-0022` → DONE: открытых 29 → 28,
`sp_ct_generate_actions` не воскресил действие (правило 7 дней), в `CT_ACTION_STATUS_LOG` две строки
аудита (`owner:webapp-test`), затем возврат в OPEN. История видна на дашборде «ДЕТАЛИ».

**Деплой (один раз, владелец, ~2 мин):** редактор Apps Script проекта EVETIS → добавить файл
`CtOwnerActions.gs` → Deploy → New deployment → Web app → *Execute as: Me*, *Who has access: Only myself*
→ скопировать `/exec` URL → `UPDATE evetis_ref.CT_CONFIG SET config_value = '<url>', updated_at =
CURRENT_TIMESTAMP() WHERE config_key = 'action_webapp_url'` (или попросить Claude). Первый клик один раз
спросит согласие на BigQuery. До деплоя статусы меняет Claude по просьбе владельца тем же `CALL`.

## 8. Визуальный QA (реальный браузер, 1 440×900, Metabase full width)

Метод: для каждой карточки в DOM измерялись `scrollWidth − clientWidth` и `scrollHeight − clientHeight`
прокручиваемых контейнеров (скрипт `ctQA` в консоли, см. ниже). Итерации: ширины колонок, высоты
карточек, разбиение статусной строки, замена длинных подписей.

| Дашборд | Карточек | Горизонтальный overflow | Внутренняя вертикальная прокрутка |
|---|---|---|---|
| EVETIS OWNER HOME (5) | 36 | **0** | **0** |
| EVETIS SALES PLAN (6) | 14 | **0** | **0** (Top-20 таблица — 15 рядов сетки) |
| ДЕТАЛИ (8) | 17 | есть (drill-down, широкие таблицы — допустимо по ТЗ) | есть |
| DAILY BRIEF (9) | 3 | 0 | 0 |

Найдено и исправлено в процессе (не тестами, а глазами):
1. Trend-плитки на 4 колонках сжимают число до «19k ₽» — ряд перестроен 5/3/5/3/4/4 колонок,
   `scalar.compact_primary_number = false`; на 3 колонках остаются только короткие значения (28 фл., 13,6 %).
2. Metabase масштабирует подсказки ширин колонок под карточку, но клампит колонку снизу 60 px:
   подсказка `48` для колонки «P» давала overflow 11 px → все подсказки ≥ 60.
3. Подсказки ширин применяются к **видимым** колонкам: со скрытой `ord` массив сдвигался на одну колонку.
4. Скалярная плитка не переносит длинную строку — полоса свежести сделана таблицей 7 колонок с
   условной раскраской и скрытым заголовком карточки.
5. `graph.max_categories` по умолчанию прячет SKU в «Other (7)» — отключён.
6. BigQuery запрещает точку в алиасе (`Факт с 09.09`) — алиасы латиницей, подписи через `column_title`.
7. Ошибка сборщика (`column_settings` на верхнем уровне) — суффиксы ₽/фл. не отображались; исправлено.

```js
// консоль браузера на localhost:3000 — карточки с overflow
const ctQA=()=>[...document.querySelectorAll('[data-testid="dashcard"]')].map(c=>{const t=(c.querySelector('h3')||{}).textContent||'';
 const s=[...c.querySelectorAll('*')].filter(e=>{const st=getComputedStyle(e);return /auto|scroll/.test(st.overflowX+st.overflowY)&&(e.scrollWidth>e.clientWidth+2||e.scrollHeight>e.clientHeight+2)});
 return {t:t.trim().slice(0,40),h:Math.max(0,...s.map(e=>e.scrollWidth-e.clientWidth)),v:Math.max(0,...s.map(e=>e.scrollHeight-e.clientHeight))}}).filter(x=>x.h||x.v);
```

## 12. Остающиеся ограничения

1. **Автозапуск включится после `terraform apply`** через workflow `infra` (шаг владельца). Всё остальное
   (процедура, guard, наблюдаемость, IAM в коде) готово; до apply Owner Home показывает возраст ручного
   обновления и STALE через 26 ч.
2. **Web-app требует одноразового деплоя владельцем** (Apps Script нельзя задеплоить из этой сессии: домен
   `script.google.com` закрыт для встроенного браузера). До деплоя колонки «Готово / В работе» пустые;
   статус меняется через Claude или `CALL`.
3. Trend-плитки Metabase показывают значение сравнения компактно («план дня: 34,5k») — ограничение
   визуализации, основное число всегда полное.
4. Цель progress-бара «Запас продан» задана константой 53,9 % (план сезона) — Metabase не читает цель из
   запроса; при новой версии плана обновить в сборщике.
5. Прогноз EOM по-прежнему = факт за плановые дни + средний темп 7 дней × оставшиеся плановые дни
   (без формы кривой) — теперь это явно помечено уверенностью и причиной.
6. Полоса свежести помечает `WB SALES ● 1 day` как норму (дневная витрина), `◔` — только для
   доменов, которые обязаны быть сегодняшними (остатки, срез ФФ, постинги Ozon).
7. Seed-действия CT-0001…0019 содержат числа от 09.09 (1 330 / 1 350 / 94); операционный план 10.09
   (745 / 956 / 314) — предмет ведения очереди владельцем, не этой фазы.
