# UNITKA 2.0 — Stage 8.2 §8: проверка логистики по SKU

Окно ставок D-30…D-1 от `LAST_CLOSED_DATE = 10.09.2026`, то есть **12.08–10.09.2026**.
Источник: `wb_raw.V_WB_FINANCE_CANONICAL`. Модель B по решению владельца **не менялась** —
это диагностика.

---

## 1. Найден дефект знаменателя

Модель B считает `DIRECT = (Σ прямых плеч «Логистика» + Σ «Доставка») / число отправлений`,
где **числом отправлений считалось число `srid` с операцией «Логистика»**. Это неверно.

Замер за окно:

```
операция     строк   srid     сумма logistics_amount
Логистика     484    444      28 027,82 ₽
Доставка      165    153       9 811,10 ₽
пересечение srid «Логистика» и «Доставка» ......... 0
```

**«Доставка» и «Логистика» — два взаимоисключающих имени одного и того же события:
прямой перевозки отправления.** Доказательство:

```
srid с операцией «Продажа» .......................... 545
из них имеют «Логистика» ............................ 404
из них имеют «Доставка» ............................. 141
404 + 141 = 545, продаж без транспортной строки ..... 0
```

Каждая проданная отправка несёт **ровно одну** из двух операций. Значит корректная
популяция отправлений окна — **597** (444 + 153), а не 444.

**Следствие:** «Доставка» попадала в числитель, но её отправления не попадали в знаменатель.
Ставка завышена примерно на треть.

```
как считается сейчас: (26 738,82 + 9 811,10) / 444 = 82,32 ₽
как должно быть:       36 147,59 / 597            = 60,55 ₽
```

Ориентир первого аудита — **60,37 ₽** — оказался верным. Он совпадает с корректным
расчётом (60,55 ₽ на сдвинутом на сутки окне), а расхождение с 82,32 ₽ объясняется ровно
пропущенными 153 отправлениями «Доставки».

Обратное плечо этим не затронуто: отказ по-прежнему = **вторая строка с тем же `srid`**,
в объединённой популяции таких 52, сумма вторых плеч 1 691,33 ₽ → **32,53 ₽ за отказ**
(в книге сейчас 32,23 ₽ — разница только от того, что «Доставка» раньше не участвовала).

Разбиение остаётся полным и непересекающимся:
`36 147,59 прямых + 1 691,33 обратных = 37 838,92 ₽ = вся «Логистика» + вся «Доставка»`.

## 3. Ответ на вопрос «почему крем для рук ~70, а Вишня и Амбра ~85–87»

В книге сейчас стоят ставки, посчитанные **на завышенном знаменателе**:
крем для рук 92,07 ₽, Амбра 89,88 ₽, Вишня 70,20 ₽. Разброс между ними складывался из двух
эффектов, и оба — артефакты знаменателя.

Разложим по компонентам так, как считала модель (делитель = только `srid` «Логистики»):

| SKU | «Логистика»/N | «Доставка»/N | сумма | доля отправок с «Доставкой» |
|---|---|---|---|---|
| Крем для рук | 65,03 | 27,04 | 92,07 | 63 из 163 = 39 % |
| Крем Амбра | 54,80 | 35,08 | 89,88 | 9 из 13 = 69 % |
| Крем Вишня | 54,30 | 15,90 | 70,20 | 4 из 16 = 25 % |

Прямое плечо у Амбры и Вишни **практически одинаковое** — 54,80 и 54,30 ₽. Вся разница
между «70» и «90» бралась из того, **как часто** отправление ехало по схеме «Доставка»,
причём эти отправления добавлялись в числитель, но не в знаменатель. Чем чаще «Доставка»,
тем сильнее завышалась ставка.

На корректном знаменателе разброс почти исчезает: **Вишня 56,16 ₽, Амбра 54,11 ₽**, а крем
для рук честно дороже (**65,98 ₽**) — у него выше само прямое плечо, что согласуется с
более крупной и тяжёлой упаковкой.

**Малая выборка** остаётся отдельным риском: у Амбры 21 отправление, у Вишни 20, при пороге
`n ≥ 10`. Одно событие «Доставки» сдвигает ставку на 2–3 ₽. Порог обсуждаем отдельно.

## 4. Что предлагается (решение за владельцем)

Модель B **не меняется**. Меняется одна строка в числителе/знаменателе `s8bsql_()`:
популяция отправлений = `srid` с операцией `IN ('Логистика','Доставка')`, а не только
`'Логистика'`. Разбиение на плечи (первая строка `srid` — прямое, вторая — обратное)
остаётся ровно тем же, просто применяется к объединённой популяции.

Эффект на сентябрь 01–10: прямая логистика падает с ≈82 ₽ до ≈61 ₽ на заказ,
обратная поднимается с 32,23 ₽ до 32,53 ₽. Доходность сентября вырастет.

Пока правка **не применена** — по условию задания «не менять модель B пока».
