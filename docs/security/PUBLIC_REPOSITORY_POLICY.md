# Политика публичного репозитория EVETIS Analytics

**Редакция 1 · 2026-10-07**

Репозиторий публичный: так продолжает работать GitHub Actions на текущем тарифе. Публичность сама по
себе не ошибка. Граница безопасности держится не на том, что «никто не увидит», а на четырёх вещах:

```
ПУБЛИЧНЫЙ КОД  +  ЧАСТНЫЕ СЕКРЕТЫ И ДОКАЗАТЕЛЬСТВА  +  СТРОГИЙ WIF  +  ЗАЩИЩЁННЫЙ main
                     +  ЗАКРЕПЛЁННАЯ ПОСТАВКА ACTIONS  +  НЕТ ПУТИ fork → production
```

Документ дополняет `docs/architecture/REPOSITORY_DATA_POLICY.md` и **заменяет** его правило «доказательства
аудита — `docs/<домен>/audit_<дата>/*.csv` в Git» для всего, что содержит значения бизнеса (§2).

---

## 1. Классы информации

| Класс | Что это | Где живёт |
| --- | --- | --- |
| `PUBLIC_OK` | код, тесты, DDL, Terraform без секретов, обобщённые runbook'и, архитектура | Git |
| `INTERNAL_METADATA` | ID проекта GCP, имена SA, имена датасетов/таблиц, ID книг Google | Git допустимо, если нужно коду; не множить в отчётах |
| `COMMERCIAL_SENSITIVE` | суммы, маржа, себестоимость, юнит-экономика, цены закупки, объёмы продаж, планы | приватное хранилище (§3) |
| `PERSONAL_DATA` | ФИО, телефоны, адреса, e-mail людей, имена покупателей, тексты обращений | приватное хранилище; в тестах — только синтетика |
| `CREDENTIAL` | токены, ключи, пароли, приватные ключи, секреты webhook | только Secret Manager; в Git — никогда |

ID проекта или e-mail сервисного аккаунта — **не секрет**: доступ решают IAM и WIF, а не тайна имени.
Но лишняя публикация облегчает разведку, поэтому в новых документах — без необходимости не повторять.

## 2. Правила для нового содержимого

1. **Учётные данные** — только Secret Manager. Тесты используют синтетику с пометкой «синтетика».
   Проверка — `tools/tests/test_public_repo_security.py::test_no_credentials_in_tracked_files`.
   Найденный настоящий секрет: **сначала ротация**, потом удаление из истории; удаление файла не помогает.
2. **Доказательства с бизнес-значениями** (выгрузки, регрессионные базы, CSV с суммами, xlsx, скриншоты
   кабинетов и дашбордов, снимки страниц браузера, логи прогонов с данными) — в приватный GCS
   (§3). В Git — только `.md` с решением, контрольными суммами (sha256) и путём `gs://…` к доказательству.
3. **Отчёты об инцидентах и аудитах безопасности** — в Git только обобщённые выводы после исправления.
   Детали открытых уязвимостей и живого состояния настроек — в приватное хранилище.
4. **Данные арендаторов** (`client_*`) — никаких выгрузок, цифр и документов арендатора в Git. Реестр
   `tenants/*/tenant.json` содержит только идентификаторы и ссылки на секреты.
5. **Документы** (декларации, ЧЗ, договоры, юридическое) — вне репозитория (`docs/legal/` уже в `.gitignore`).
6. **Тексты покупателей** для golden-наборов — без имён покупателей; имя заменять синтетическим.

## 3. Где живёт приватное

| Вариант | Для чего | Статус |
| --- | --- | --- |
| **B. Приватный GCS** `evetis-audit-evidence-<номер проекта>` | доказательства аудитов, выгрузки, откаты с данными | **основной**: public access prevention, только владелец, версии и soft delete |
| A. Приватный репозиторий-спутник | документы, которым нужен diff/ревью (runbook'и с данными, разборы инцидентов) | по решению владельца; Actions там не нужны |
| C. Личное хранилище владельца (Drive/проекты) | рабочие материалы, переписка, документы поставщиков | уже используется |

Workflows и инструменты, производящие доказательства, пишут их **сразу** в вариант B
(`gsutil cp … gs://…/evidence/<домен>/<дата>/`), а в Git кладут только опись с sha256.

## 4. Инварианты CI/CD (проверяются тестами)

`tools/tests/test_public_repo_security.py` (запускается `sql-current` на каждом PR):

- внешние actions закреплены полным SHA коммита с комментарием версии; одна action — один SHA во всех файлах;
- нет триггеров `pull_request_target`, `workflow_run`, `repository_dispatch`, `issue_comment` и подобных;
- у каждого workflow явные `permissions` верхнего уровня, нет `write-all`/`read-all`;
- workflows, достижимые из PR (`ci.yml`, `sql-current.yml`), не запрашивают `id-token`, не имеют прав записи,
  не используют секреты, WIF и SA;
- привилегированные SA встречаются только в файлах, которым их разрешают привязки WIF
  (`infra/terraform/wif.tf`): deployer — `deploy-prod`/`deploy-shadow`, apply — `infra`/`scheduler-control`,
  tenant-provisioner — `tenant-infra`; эти файлы запускаются только `workflow_dispatch` или push в `main`;
- привилегированные job'ы привязаны к GitHub Environment (`production`, `infra`);
- входы `workflow_dispatch` и данные события не подставляются `${{ }}` в текст shell — только через `env`;
- `actions/checkout` с `persist-credentials: false` везде, кроме публикатора AE (пушит `ae/*`).

Привязки WIF к живому GCP проверяют `python -m tools.autonomy.wif_check --live` и
`python -m tools.autonomy.wif_domains --live` (только чтение).

## 5. Целевые настройки GitHub (вне кода)

Меняются только владельцем, по отдельному ACK, с планом отката:

- **`main`**: ruleset — запрет force push и удаления; изменения только через PR; обязательная проверка
  `sql-current` (единственная, что идёт на каждом PR; `ci` фильтрует пути); автоматизация (`GITHUB_TOKEN`)
  не пушит в `main`. Обязательное ревью владельца кода при одном сопровождающем заблокировало бы его же
  слияния — включать только с обходом для владельца или после появления второго рецензента.
- **Environments** `production` и `infra`: правило ветки развёртывания — только `main`; обязательный
  рецензент там, где это доступно на тарифе.
- **Безопасность репозитория**: secret scanning и push protection, Dependabot alerts, private vulnerability
  reporting; CodeQL — по решению владельца (добавляет прогоны на PR).
- **Actions**: обязательное закрепление SHA на уровне репозитория (`sha_pinning_required`), когда все
  workflows закреплены (выполнено этим PR).

## 6. Перенос существующего

Опись уже опубликованного (по путям и классам) и план переноса ведутся **вне** публичного репозитория —
в приватном хранилище §3: публичная карта «где лежит чувствительное» сама была бы утечкой. Перенос —
отдельной задачей владельца; удаление из рабочего дерева не убирает файлы из истории, а переписывание
истории ради коммерческих (не учётных) данных — отдельное решение с оценкой ущерба.
