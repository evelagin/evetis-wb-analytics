# UNITKA 2.0 — событийная модель логистики (вариант B), сентябрь 2026

Решение владельца 11.09.2026. Книга «Юнитка_Evetis Cosmetics», лист `WB_Юнит_2025`,
строки 735–768, 24 сентябрьских блока. Код: `apps-script/UnitkaS8b.gs` (`unitka2.0/v8.3.0`).

**Соглашение:**

```
LOGISTICS_DAY = GROSS_ORDERS × DIRECT_LOGISTICS_RATE + CANCELS × REVERSE_LEG_RATE
```

Не `CANCELS × FULL_CANCEL_LOGISTICS`: прямое плечо отказанного заказа уже оплачено
внутри `GROSS_ORDERS` (колонка «Заказы факт» — валовые заказы, отменённый заказ в них
входит), и списание полной логистики отказа посчитало бы это плечо дважды.

**Итог:**

```
DIRECT LOGISTICS DOUBLE COUNT ... 0
REVERSE LOGISTICS DOUBLE COUNT .. 0
SUMMARY RECONCILIATION .......... PASS
FORMULA ERRORS .................. 0
SEPTEMBER FINANCIAL MASTER READY  YES
```

---

## 1. Откуда берутся плечи

Отдельной операции «обратная логистика» в финотчёте WB нет. У отказа появляется
**вторая строка «Логистика» с тем же `srid`**. Разбиение: больший из двух — прямое
плечо, меньший — обратное (аудит 01.06–09.09: 63,48 против 33,48 ₽).

`s8bsql_()` считает по `wb_raw.V_WB_FINANCE_CANONICAL` за окно D-30…D-1 от зеркала
`LAST_CLOSED_DATE`:

| величина | формула |
|---|---|
| `DIRECT` | (Σ прямых плеч + Σ «Доставка») / число отправлений окна |
| `REVERSE` | Σ обратных плеч / число отказов окна |

Ставки **не хардкодятся** — пересчитываются каждым прогоном.

## 2. Факт на окне 11.08–09.09.2026

```
отправлений ......... 475        отказов ............ 44
прямые плечи ........ 28 685,14 ₽
«Доставка» .......... 8 621,46 ₽
обратные плечи ......  1 409,00 ₽
вся логистика окна .. 38 715,60 ₽ = прямые + обратные + доставка
DIRECT  = (28 685,14 + 8 621,46) / 475 = 78,54 ₽ / валовый заказ
REVERSE = 1 409,00 / 44               = 32,02 ₽ / отказ
```

**Расхождение с ориентиром 60,37 ₽ — объяснимое и намеренное.** 60,37 ₽ в аудите —
это только прямое плечо «Логистики» (28 685,14 / 475 = 60,39 ₽). В книге строка
логистики всегда включала ещё и операцию **«Доставка»** — 8 621,46 ₽ за окно,
то есть 18,15 ₽ на заказ. Выбросить её значило бы тихо убрать из сентября 23 %
реальной логистики. Поэтому `DIRECT = 60,39 + 18,15 = 78,54 ₽`, и обе компоненты
печатаются в логе раздельно. Если владелец хочет считать «Доставку» отдельной
статьёй, это одна правка в `s8bsql_()` — числитель `a.fwd` без `d.dlv`.

**Непересечение числителей проверяется в приёмке:**
`прямые + обратные + доставка = вся логистика окна`, пересечение = 0,00 ₽.
Обратные плечи физически вынесены из числителя `DIRECT` — это и есть доказательство,
что старого двойного счёта («вся логистика / выкупы» = 70,01 ₽) больше нет.

## 4. Что изменилось в книге

**Ставка обратного плеча живёт в зеркале** — ячейка `WB737` рядом с зеркалом
`LAST_CLOSED_DATE` (`WB736`), с подписью в `WA737` и именованным диапазоном
**`REVERSE_LEG_RATE`**. Старый параметр `$F$45` = 50 ₽ **не тронут**: он мог
использоваться августом, а август трогать нельзя. В сентябрьских формулах его
больше нет ни разу.

**Дневная доходность блока** (колонка `W` у эталона), все 24 блока × 30 дней = 720 формул:

```
было:   Q*AI - X - AG - S*AI + Y
стало:  Q*AI - X - AG - S*(AI + AF + REVERSE_LEG_RATE) + Y
```

Разбор добавки: `-S*AI` снимает экономику непроданной единицы (как и раньше);
`-S*AF` возвращает **прямое** плечо, которое WB списал по валовому заказу и которое
вместе с экономикой ошибочно снималось; `-S*REVERSE_LEG_RATE` добавляет **обратное**
плечо. Итого логистика дня = `Q*AF + S*REVERSE` — ровно по соглашению.

**MTD-строка логистики блока** (`AF767`, 24 формулы) перестала быть только прямой:
к `SUMPRODUCT(AF×Q)` добавлено `SUM(отмены)×REVERSE_LEG_RATE`.

**Сводка `I767`**: `=SUM(I737:I766) - H767*$F$45` → `=SUM(I737:I766)`.
Отмены теперь учтены внутри блоков; повторное вычитание в сводке было бы двойным счётом.

**`s8rates()` больше не пишет колонку логистики** — только комиссию. Иначе следующий
её прогон вернул бы ставку «вся логистика / выкупы» и вместе с ней двойной счёт.

## 5. Как проверяется отсутствие двойного счёта

Структурно, а не на глаз. В цепочке доходности ссылка на колонку логистики должна
встречаться ровно столько раз, сколько плеч мы намерены списать:

| формула | ссылок на `AF` | ссылок на `REVERSE_LEG_RATE` |
|---|---|---|
| `AI` — доходность 1 шт | ровно 1 (прямое плечо проданной единицы) | 0 |
| `W` — доходность дня | ровно 1 (прямое плечо отменённой единицы) | ровно 1 |
| `I767` сводки | — | старой константы отмен нет ни одной |

Проверено на 720 дневных формулах и 720 формулах `AI`: отклонений 0.

```

прямая логистика Q×DIRECT ... 9 938,53 ₽
обратная логистика отмен .... 192,14 ₽ (6 × 32,02)
было по старой модели ....... отмены × 50 ₽ = 300,00 ₽ в сводке,
                              прямое плечо отмен не списывалось вовсе

```

Сверка сводки с суммой 24 блоков по 9 закрытым дням: `max |Δ| = 0,0000`.
`I767` = сумме дневных, `|Δ| = 0,0000`.

## 7. Для Engine v1 (не начат)

1. Обе ставки — rolling D-30…D-1 из `V_WB_FINANCE_CANONICAL`, пересчёт каждым прогоном.
2. Обратное плечо — **магазинная** ставка; собственная ставка SKU только при `n ≥ 10` отказов.
3. Дневной факт обратного плеча закрыть нельзя: удержание приходит через 2–6 недель
   после заказа. Дневная строка закрывается модельной ставкой, факт — задним числом
   при пересчёте, расхождение уходит в сверку.
