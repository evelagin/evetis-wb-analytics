# Heldi S4 — ежедневный CURRENT не зависит от локального STOP истории (2026-10-23)

Решение владельца 2026-10-23: непрерывная ежедневная загрузка `catalog`, `stocks`, `prices`,
`finance_accrual`, даже когда независимый лист FULL_HISTORY остановлен. Выпуск объединён с S‴-b
(удалённые платформой исполнения закрытых исторических claim, PR #375).

## Что меняется

1. `full_controller.historical_gate` — бывший STOP-шлюз пробуждения, вынесенный в функцию без
   изменения логики: та же перепроверка единого `stop_acceptance`, та же отсрочка при другом
   контроллере, те же автоматические восстановления. Новое только в конце: нерешённый STOP
   больше не завершает пробуждение, если `current_independence.admit` доказал допуск; тогда
   выполняется только CURRENT, очередь FULL закрыта. Ни одно исключение не перехватывается.
2. `current_independence.admit` — допуск на каждом пробуждении:
   - каждый нерешённый STOP принадлежит FULL локально: STOP листа FULL (`leaf_wake`) либо
     типизированный диагноз сверки листа (`RUNTIME_TERMINAL`, `PERSISTED_SOURCE_RECONCILIATION`,
     `RECONCILIATION_APPEND`) с контекстом шарда этого манифеста и без отправленной записи в
     журнале записей. Нетипизированный STOP, неизвестный исход записи, этапы аренды, чекпойнта,
     границы отправки, закрытия, привязки, квоты, корня и монитора — глобальные;
   - общая аренда: самое новое поколение из журнала аренд и таблиц освобождено маркером `LD_`
     своего точного владельца, либо удерживается принятым (receipt) запуском одного шарда CURRENT,
     который это пробуждение сверяет первым. Истечение аренды и прошедшее время — не доказательство;
   - ни у одного исторического шарда нет выбранного intent без сверки; нет стоп-крана оператора;
   - все обычные Ozon Scheduler PAUSED (нет параллельного писателя); активный runtime по-прежнему
     отклоняется preflight отправки.
   Проверки identity, привязки, учётных данных, дескриптора развёртывания, claim и preflight отправки
   выполняются на пути CURRENT без изменений.
3. `current_controller.INDEPENDENT_ENTITIES` — новая работа CURRENT выбирается только для четырёх
   сущностей; реклама и FBO выключены до своих исправлений. Политика владельца не переписывается;
   ранее выбранные intent и receipt любой сущности по-прежнему сверяются первыми; PARTIAL одной
   сущности не останавливает остальные.
4. Поле релиза `current_independence_version` (требует S‴-a) и адаптер `current_independence_adapter`.

Не входит (S4.1): локальная обработка FAILED-запуска сущности CURRENT. Сейчас такой сбой остаётся
глобальным STOP (типизированный `RUNTIME_TERMINAL` без контекста FULL), как и раньше.

## Проверка

`tools/tests/test_current_independence.py` и `python -m tools.tenancy.current_independence_image_check`:
классы STOP; допуск при освобождённой аренде (в том числе после истечения таблицы аренды — по
журналу и маркеру освобождения); отказ при глобальном STOP, открытом историческом intent, стоп-кране,
неосвобождённой новой аренде, истёкшей без освобождения аренде, чужом владельце освобождения,
неоднозначном владельце, отсутствии доказательств, включённом обычном Scheduler; шлюз пробуждения
сохраняет перепроверку и автоматическое восстановление; выбор только четырёх сущностей, сверка уже
выбранного intent рекламы, изоляция PARTIAL.

## Порядок в production (по пакетному OWNER ACK)

Базис: generation 55 PAUSED (`806489c6`), 8 маркеров S‴-a, STOP `8ad33cc6` не восстановлен. STOP
`8ad33cc6` нетипизирован и по правилу выше глобальный, поэтому пакет включает его точное восстановление
`FULL_TERMINAL_GATE_AFTER_RECONCILED_PAGE_V1` (4 записи, отрепетировано 22.10). Далее bootstrap PAUSED →
ENABLED → resume только `tenant-backfill-tick`. Приёмка — первые данные четырёх сущностей в BigQuery.
