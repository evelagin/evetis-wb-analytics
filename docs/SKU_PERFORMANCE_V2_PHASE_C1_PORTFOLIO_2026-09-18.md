## 2. Фильтры

| Фильтр | Тип | Цель | По умолчанию |
| --- | --- | --- | --- |
| «Период» | date/all-options | `V_DASH_SKU_PERFORMANCE_V2_DAILY.day` (6672) | **`past30days-from-1days`** — 30 дней, заканчивающиеся позавчера |
| «Товар» | string/=, несколько | `V_DASH_SKU_PERFORMANCE_V2_DAILY.product_name_short` (6675) | весь ассортимент |

**Почему период по умолчанию кончается позавчера.** Финансовый отчёт WB приходит с задержкой 1–2 дня. С периодом
«последние 30 дней» (до вчера) вклад и маржа при каждом открытии были бы «н/с», а статус — жёлтым из-за хвоста.
Сдвиг на день даёт сравнимые экономические KPI с первого открытия. Любой другой период выбирается как обычно.
**Решение владельца (final refinement 18.09): сдвиг сохраняется, к обычным «последним 30 дням» не возвращаемся.**
Свежесть и покрытие по-прежнему показывает строка статуса.

Границы периода для TVF берутся из фильтра: `MIN/MAX(day)` слоя. Сегодняшних суток в слое нет, поэтому период,
выбранный «до сегодня», фактически кончается вчерашним днём. Строка статуса всегда показывает фактические даты.

## 4. Metric mapping (все значения — backend Phase B, ratio-of-sums)

Карточки суммируют строки `TVF_SKU_PERFORMANCE_V2_PERIOD` по выбранным товарам. Для всего ассортимента это
ровно строка «Портфель» TVF, для одного товара — строка этого SKU (регрессия §8). Никаких других расчётов нет.

| Показатель | Формула | Сравнение |
| --- | --- | --- |
| Заказы | Σ `cur_orders_gross_units` | Δ % при `orders_cmp` |
| Выкупы | Σ `cur_buyout_units` | Δ % при `sales_cmp` |
| Выкуп | Σ `cur_cohort_buyout_orders` / Σ `cur_cohort_resolved_orders`; 🟡 — есть заказы без исхода | Δ п.п. при `orders_cmp` и зрелой когорте прошлого окна |
| Ср. цена | Σ `cur_orders_gross_seller_price_rub` / Σ `cur_orders_gross_units` | Δ % при `orders_cmp`; «мало данных» при < 10 заказах в окне |
| Реклама | Σ `cur_ads_attributed_rub` (атрибуция) | Δ % при `drr_cmp` |
| ДРР | Σ реклама / Σ `cur_buyout_seller_price_rub` | Δ п.п. при `drr_cmp` |
| Вклад SKU после себестоимости | Σ `cur_contribution_after_cogs_rub` | Δ ₽ при `econ_cmp` (процент от отрицательной базы бессмыслен) |
| Маржа вклада | вклад / Σ `cur_fin_seller_price_rub` | Δ п.п. при `econ_cmp` |
| Таблица: ₽ / выкуп | `cur_contribution_after_cogs_per_buyout_rub` | — |

**Сопоставимость** (как в TVF): одинаковое число покрытых суток в обоих окнах и текущее окно покрыто целиком.
Иначе вместо изменения — «н/с», искусственного «0 %» нет.

**Контракт малой выборки (C1 closeout, 18.09): отображение ≠ право на сигнал.** Малая выборка и несопоставимость —
разные вещи:

| Ситуация | KPI | Таблица (Δ цены, Δ заказов) | «Требуют внимания» |
| --- | --- | --- | --- |
| Окна технически несопоставимы (покрытие) | «н/с» | пусто | правило 3–4 не проверяется |
| В прошлом окне базы нет (0) | «—» | пусто | — |
| Сопоставимо, база ≥ 10 в обоих окнах | «↓ 35,8 %» | фактическое Δ | правила 1, 3–5 проверяются |
| Сопоставимо, база < 10 хотя бы в одном окне | «↓ 93,5 % · мало данных» | фактическое Δ + «малая выборка» в «Статусе» | правила 1, 3–5 **не** срабатывают |

- Фактическое значение показывается всегда; при отсутствии базы (0 заказов / выкупов) — «—», плитка не пустеет.
- Пометка нейтральная: без цвета, стрелка та же. Цвет по-прежнему только у отрицательного вклада в таблице.
- База надёжности по KPI (порог `min_reliable_units` = 10 из Phase B, не менялся): заказы и ср. цена — заказы;
  выкупы, ДРР, вклад, маржа — выкупы; % выкупа — завершённые заказы. «Реклама, ₽» пометки не получает: это
  потраченные деньги, а не выборочная оценка.
- В таблице «малая выборка» = backend `low_sample` (сейчас < 10 заказов и < 10 выкупов) **или** показанное Δ
  посчитано на базе < 10 заказов в одном из окон — поэтому для одного товара KPI и строка таблицы согласованы.

**Зрелость когорты для подачи.** В TVF флаг строгий: ни одного заказа без исхода. Из-за двух «вечных» заказов он
никогда не выполняется для старых окон. Поэтому для 🟡 и для сравнения окно считается зрелым, если в нём нет
заказов без исхода **или** оно закончилось ≥ 21 дня назад: p99 «заказ → выкуп» = 18 дней (Phase A §F).
Флаг Phase B не меняется.

**Цвет:** стрелки ↑↓ нейтральные (цена ↑ — не «хорошо»). Красная заливка есть только у отрицательного вклада
в таблице; 🟡 / 🔴 — только статус данных и незавершённый выкуп.

## 5. Описания (tooltips)

- **Ср. цена** — «Средняя установленная продавцом цена до СПП, взвешенная по заказанным единицам: сумма цен всех
  заказанных единиц / число единиц (включая отменённые заказы). Изменение цены не оценивается как хорошее или
  плохое. На уровне всего ассортимента зависит и от набора проданных товаров.»
- **Выкуп** — «Доля завершённых заказов периода, которые были выкуплены: выкуплено / (выкуплено + отменено)…
  незавершённые заказы не считаются отказами…»
- **Реклама** — «…атрибутированные товарам по статистике кампаний WB… Могут немного отличаться от рекламного
  биллинга WB в Executive — это разные контракты, распределение не выполняется.»
- **Вклад** — «Начисление WB за товар минус прямая логистика, доступное хранение по товару, атрибутированная реклама
  и себестоимость. Общие расходы аккаунта… не распределяются, поэтому сумма не равна результату Executive. Это не прибыль.»
- **Маржа** — «Вклад SKU после себестоимости / выручка по цене продавца по финансовому отчёту WB (продажи минус возвраты).»

Полные тексты — в `tools/metabase_sku_v2_portfolio_build.py` и в снимке карточек.

## 6. «Требуют внимания» — правила C1

| # | Правило | Условие | Основание порога |
| --- | --- | --- | --- |
| 1 | Отрицательный вклад | вклад после себестоимости < 0 и ≥ 10 выкупов | объективно |
| 2 | Реклама без выкупов | реклама > 0 и 0 выкупов | объективно (правило dashboard 3) |
| 3 | Резкое падение заказов | Δ заказов ≤ −50 %, ≥ 10 заказов в обоих окнах, окна сопоставимы, период ≥ 14 дней | **p5** Δ заказов SKU между соседними 14-дневными окнами (n = 80; p10 = −44 %) |
| 4 | Падение выкупа | Δ ≤ −14 п.п., ≥ 10 завершённых заказов в обоих окнах, обе когорты зрелые | **p5** Δ % выкупа (n = 80; p10 = −12,5 п.п.) |
| 5 | Высокий ДРР | ДРР ≥ 41 %, ≥ 10 выкупов | **p95** ДРР SKU-окна (n = 100; p90 = 34,2 %) |

- **Статус порогов: эмпирические пороги V1, основанные на историческом распределении EVETIS, а не универсальные
  бизнес-нормативы** (принято владельцем 18.09). Распределения — непересекающиеся 14-дневные окна SKU за
  20.04–30.08.2026, только окна с ≥ 10 единиц; порог = «самые крайние 5 %». Новых порогов нет; пересмотр — после
  накопления истории или по бизнес-нормам владельца.
- **Вывод:** в строке — товар, артикул и **факты** («Заказы ↓ 56,7 % (60 → 26) · цена ↑ 14,7 %»), без причинности. Несколько сработавших правил — в одной строке через «·».
- **Лимит** — 6 строк. Если сигналов нет — одна строка «✅ Нет товаров, требующих внимания».

**Порядок строк (детерминированный, без составного балла).** Каждый товар получает ранг и величину по своему
**первому** (самому приоритетному) сработавшему правилу; остальные его сигналы дописываются в ту же строку.

```
ORDER BY sev_rank ASC, sev DESC, nm_id ASC  LIMIT 6
```

| `sev_rank` | Правило | `sev` (больше — выше) |
| --- | --- | --- |
| 1 | Отрицательный вклад | −вклад, ₽ (больший убыток выше) |
| 2 | Реклама без выкупов | реклама, ₽ |
| 3 | Падение заказов | −Δ заказов, % |
| 4 | Падение выкупа | −Δ выкупа, п.п. |
| 5 | Высокий ДРР | ДРР |

Последний ключ — `nm_id` по возрастанию: при равенстве порядок не зависит от плана BigQuery.
Проверка на 27.07–23.08 (8 сигналов): Крем Руки −24 637 ₽ → Тоник АКНЕ −3 176 → Крем Амбра −2 722 (+ДРР) →
Тоник УВЛ −1 549 → Сыворотка АКНЕ −482 → Энзимная пудра −471; за лимитом — Крем Вишня (−25 ₽) и
Набор тон+сыв+крем АКНЕ (падение заказов). Порядок карточки = независимый расчёт на Python.
- **Малая выборка** сигналов не даёт, кроме правила 2 (это факт, не оценка): правила 1, 3–5 требуют флагов
  надёжности Phase B. Фактическое Δ при этом видно в KPI и таблице с пометкой (§4). Пример: Крем УВЛ, 18.08–16.09 —
  заказы 3 против 46 (↓ 93,5 %) показаны, но в «Требуют внимания» его нет.

## 11. Известные ограничения

1. **Строка статуса** — текстовый scalar без переноса, Metabase подгоняет шрифт под длину. При 1440 px длинная строка всего ассортимента помещается; у короткой строки одного товара шрифт крупнее, и последний символ может срезаться («…16/30 дн»). На экранах уже — обрежется. Полное объяснение — в подсказке.
9. **Размер шрифта KPI** подгоняется Metabase под длину текста: плитки с пометкой «мало данных» мельче соседних. Текст не обрезается.
2. **KPI-изменения без цвета.** Стрелки нейтральные: текстовый scalar Metabase не красит часть строки. Хорошо/плохо читается из смысла показателя, и так выполнено правило «цена ↑ ≠ хорошо».
3. **Средняя цена всего ассортимента** зависит от набора проданных товаров. Для анализа «цена → спрос» нужен фильтр «Товар» (оговорено в подсказках; детальный анализ — C2).
4. **Период по умолчанию** не включает вчерашний день (задержка финансов WB). Подпись фильтра — «Предыдущие 30 дня, начиная 1 день назад».
5. «Требуют внимания» ограничены 6 строками. В окончательном периоде 27.07–23.08 сигналов 8, два последних по порядку §6 не видны; все сигналы по товару — в таблице.
6. **Хранение по товарам — с 01.09.2026.** Для более ранних периодов вклад без хранения; об этом говорит статус («без хранения по товарам» / «хранение по товарам N/M дн.»).
7. Высота таблицы рассчитана на 22–25 товаров. При одном выбранном товаре под таблицей остаётся пустое место (Metabase не подстраивает высоту карточки).
8. Длинные названия наборов в таблице обрезаются («Набор тоник+сыворотка А…»); полное название — при наведении.
