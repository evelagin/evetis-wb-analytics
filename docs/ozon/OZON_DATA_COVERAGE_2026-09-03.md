# Фактическое покрытие данных Ozon

Дата: 2026-09-03, после первого production runtime-прогона. Только чтение из Ozon.

## Главное уточнение о глубине

**Глубина истории поставок и глубина истории продаж — разные величины.**
История заявок на поставку начинается 2025-04-18. Это **не** значит, что с апреля 2025
есть продажи.

Проверено вызовами API отдельно по каждой сущности:

| Проверка | Результат |
| --- | --- |
| `/v3/posting/fbo/list` январь 2025 | 0 отправлений |
| `/v3/posting/fbo/list` апрель 2025 | 1 отправление |
| `/v3/posting/fbo/list` сентябрь 2025 | 100 (упёрлось в limit) |
| `/v1/finance/accrual/by-day` 2025-04-20 | 0 начислений |
| `/v1/finance/accrual/by-day` 2025-09-15 | 17 начислений |

Вывод: **API отдаёт продажи примерно с апреля 2025 и финансы примерно с сентября 2025.
В BigQuery сейчас загружено только с 2026-06-01** — это граница выбранного окна backfill,
а не ограничение API. Разрыв реальный и описан ниже.

## Остающиеся исторические пробелы

1. **Продажи до 2026-06-02.** API отдаёт примерно с апреля 2025, в хранилище нет.
   Закрывается запуском runtime с `SINCE`/`UNTIL` — механизм уже есть, отдельного кода не нужно.
2. **Финансы до 2026-06-01.** API отдаёт примерно с сентября 2025.
3. **Реклама до 2026-06-01.** Не проверялась на большую глубину.
4. **История остатков до 2026-08-31 не существует нигде** — API отдаёт только текущий снимок.
   Восстановлению не подлежит, серия копится вперёд.
5. **Каталог, цены, кластеры** — снимки, ретроспективы нет по природе.
6. `ACTUAL_RECEIPT_TIME` и `ACTUAL_RECEIPT_QUANTITY` по поставкам = `NOT_PROVEN`.

## Ручные источники, оставшиеся вне пайплайна

- Публичная цена на полке и цена с картой Ozon — только браузером, в ingestion не входит.
- Позиции в поисковой выдаче — Sellmonitor, отдельный контур.
- Остатки внешнего фулфилмента — ручной снимок владельца.

---

## A. Глубина API против глубины хранилища

`/v3/posting/fbo/list` и `/v1/finance/accrual/by-day` отдают историю **раньше**, чем
загружено в BigQuery. Текущее начало истории продаж в хранилище — **2026-06-01/02** —
задано выбранным окном первичного backfill, а **не ограничением API**.

## B. История остатков

Данных об остатках **до 2026-08-31 не существует ни в одном источнике**: API отдаёт
только текущий снимок. Восстановлению задним числом не подлежит.
Серия накапливается вперёд начиная с 2026-08-31.

## C. Поздние финансовые данные — ожидаемое поведение

Начисления Ozon проводятся с задержкой. Канонические финансовые и рекламные показатели
Stage 2.1 — это **снимки на момент выгрузки**, а не окончательные величины.
При работе lookback они могут вырасти.

**Наблюдённый случай, 2026-09-03:**

| | |
| --- | --- |
| CPC (тип 41) за 01.06–31.08 в Stage 2.1 | **82 604,23 ₽** |
| То же после первого runtime-прогона | **84 330,90 ₽** |
| Дельта | **+1 726,67 ₽** |
| Причина | начисления за **31.08**, проведённые после выгрузки 01.09 и подхваченные 14-дневным lookback |

Это не дефект загрузки и не расхождение сверки. Любые исторические финансовые итоги
следует датировать моментом их расчёта.
