## 1. Слои прибыли

Ровно четыре слоя, каждый с единственной формулой.

```
L1  GROSS_SELLER_CONTRIBUTION
  = SELLER_BASE_REVENUE
  − PRODUCT_COGS
  − COMMISSION
  − DIRECT_VARIABLE_MARKETPLACE_COSTS

L2  CONTRIBUTION_BEFORE_ADS
  = GROSS_SELLER_CONTRIBUTION
  − STORE_LEVEL_VARIABLE_COSTS
  − OTHER_MARKETPLACE_COSTS_EX_ADS

L3  CONTRIBUTION_AFTER_ADS_BEFORE_FIXED
  = CONTRIBUTION_BEFORE_ADS
  − ADVERTISING

L4  MARKETPLACE_CONTRIBUTION_PROFIT
  = CONTRIBUTION_AFTER_ADS_BEFORE_FIXED
  − MARKETPLACE_FIXED_COSTS
  + COMPENSATIONS
```

⚠️ **Заморожены формулы, а не значения.** Витрины — представления,
поэтому числа меняются с каждой загрузкой. Живой источник —
`ozon_mart.V_OZON_LIFETIME_PNL`. Таблица ниже — снимок для сверки
арифметики, а не контрольные константы.

## 3. ДРР — два разных порога, оба обязаны называться полностью

**Запрещено писать «безубыточный ДРР» без указания какой.**

```
actual_drr_pct
  = ADVERTISING / SELLER_BASE_REVENUE

variable_break_even_drr_pct
  = CONTRIBUTION_BEFORE_ADS / SELLER_BASE_REVENUE

full_marketplace_break_even_drr_pct
  = (CONTRIBUTION_BEFORE_ADS − MARKETPLACE_FIXED_COSTS + COMPENSATIONS)
    / SELLER_BASE_REVENUE
```

Значения на 2026-09-04:

| Показатель | % |
|---|---:|
| **actual_drr_pct** | **27,8271** |
| **variable_break_even_drr_pct** | **27,4470** |
| **full_marketplace_break_even_drr_pct** | **21,4937** |

**Вывод, который следует из этих чисел:**

- реклама **превышает** переменную ёмкость вклада на **0,38 п.п.** —
  L3 отрицателен (−6 766,80 ₽);
- реклама **превышает** полную ёмкость маркетплейса на **6,33 п.п.**

## 4. Полнота комиссии — обязательный флаг

Покрытие выручки **100 %**. Покрытие комиссии — **нет**.

| Поле | Значение |
|---|---:|
| `commission_coverage_qty` | **1 956** |
| `commission_missing_qty` | **6** |
| `commission_missing_revenue` | **7 417,00 ₽** |
| `commission_uncertainty_lower` | **1 335,06 ₽** (7 417,00 × 0,18) |
| `commission_uncertainty_upper` | **3 856,84 ₽** (7 417,00 × 0,52) |

0,18 и 0,52 — **минимальная и максимальная фактически наблюдаемые ставки**
на 1 919 строках. Это границы, а не оценка. **Середина не подставляется.**

Итог маркируется `CANONICAL_KNOWN_CONTRIBUTION`:

```
CANONICAL_KNOWN_CONTRIBUTION = −112 750,57 ₽   (−6,33 %)
истинный вклад ∈ [−116 607,41 ; −114 085,63]   (−6,55 % … −6,41 %)
```

Знак: недостающая комиссия — **расход**, поэтому истинный вклад **ниже**
заявленного. Называть P&L полностью точным без этого флага запрещено.

## 5. Признание реализации

`realized` = `postings.status = 'delivered'`. Отменённый заказ не признаётся.
Возвраты: денежный эффект включён (11 443,32 ₽), **количество NOT_PROVEN** —
статуса возврата в `RAW_OZON_POSTINGS_FBO` нет.

## 6. Что в P&L маркетплейса не входит

Налог УСН, generic-сертификация, `PREPAID_MARKING`, консультации ВЭД,
бухгалтерия, персонал, офис. Эти расходы относятся ко всему бизнесу,
включая WB, и политика разнесения между каналами не определена.

## 7. Запреты

1. Метрика с двумя определениями.
2. `buyer_paid` вместо `seller_base`.
3. «Безубыточный ДРР» без указания какой из двух.
4. Аналитическое разнесение там, где есть прямая атрибуция.
5. Разнесение расходов уровня магазина на SKU ради 100 % покрытия.
6. Молчаливая подстановка нуля вместо отсутствующей комиссии или COGS.
7. Применение текущего тарифа к истории — комиссия только фактическая.
8. Выдавать `TRAILING_OBSERVED` за действующий тариф. Наблюдённая
   эффективная ставка комиссии за окно и тариф Ozon — разные величины;
   вторая на 2026-09-04 `NOT_PROVEN`.
9. Принимать решения по витрине при `agent_decision_gate =
   DECISIONS_BLOCKED_SOURCE_NOT_FRESH`.

## 8. Где мост живёт физически

Реализация — Stage 3.4C, ACK владельца 2026-09-04.
DDL: `sql/ozon/stage3_4c_ozon_mart.sql`, откат: `sql/ozon/stage3_4c_rollback.sql`.

**Все пять объектов — представления.** Материализованных таблиц в
`ozon_mart` нет: витрина пересчитывается при каждом чтении и устареть
относительно `ozon_raw` физически не может. Префикс `FCT_` обозначает
зерно факта, а не способ хранения (Stage 3.4C.3).

| Объект | Тип | Зерно | Какие слои несёт |
|---|---|---|---|
| `ozon_mart.FCT_OZON_PNL_MONTHLY` | VIEW | месяц | L1, L2, L3, L4 |
| `ozon_mart.FCT_OZON_SKU_PNL_MONTHLY` | VIEW | месяц × `internal_sku` | вклад до и после рекламы; **L4 нет** |
| `ozon_mart.V_OZON_MART_FRESHNESS` | VIEW | магазин | контракт свежести, слоёв не несёт |
| `ozon_mart.V_OZON_LIFETIME_PNL` | VIEW | вся история | L1, L2, L3, L4 |
| `ozon_mart.V_OZON_SKU_UNIT_ECONOMICS_CURRENT` | VIEW | `internal_sku`, окно 180 дней | юнит-экономика, только аналитика |

`FCT_OZON_PNL_DAILY` не создан — решение владельца.

**Свежесть.** Решения по витрине принимаются только при
`V_OZON_MART_FRESHNESS.agent_decision_gate = 'DECISIONS_ALLOWED'`.
При `STALE`, `PARTIAL_SOURCE_UPDATE` или `REFRESH_FAILED` агент обязан
отказаться от вывода, а не «оценить приблизительно».

**Юнит-экономика — задняя, не прогнозная.**
`V_OZON_SKU_UNIT_ECONOMICS_CURRENT` несёт `economics_mode =
TRAILING_OBSERVED` и `forward_pricing_ready = FALSE`. Наблюдённые
средние за 180 дней **не являются** действующими тарифами Ozon;
действующая комиссия документально не подтверждена. Прогнозное
ценообразование — Stage 3.4D.

**Почему на уровне SKU нет L4.** L4 требует вычесть `MARKETPLACE_FIXED_COSTS`
и добавить `COMPENSATIONS`; ни то ни другое на SKU не разносится (запрет 5).
Поэтому колонки `l4_*` в SKU-марте отсутствуют, а
`full_marketplace_break_even_drr_pct` там равен `NULL`. NULL означает
«не разносится», а не «неизвестно», и заполнять его пропорционально выручке
запрещено.

**Атрибуция прямых расходов на SKU** — две ветки, и обе обязаны использовать
один и тот же список типов `(32,29,28,98,30,1,59,45,78,9,79)`:

- finance-строка несёт `posting_number` → месяц берётся от `order_date` продажи;
- finance-строка несёт только `sku` (например тип 78) → месяц от даты начисления.

Разные списки в двух ветках роняют расходы между ними: так были потеряны
24,00 ₽ типа 78. Ошибка исправлена, списки разводить обратно нельзя.
