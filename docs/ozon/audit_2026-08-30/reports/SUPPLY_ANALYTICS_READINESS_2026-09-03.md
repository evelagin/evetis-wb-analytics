## Доказуемость связки поставка → склад → кластер → остаток → продажи

| Переход | Ключ | Результат |
| --- | --- | --- |
| Поставка → склад | `supplies[].storage_warehouse.warehouse_id` | **28 из 28** есть в официальном справочнике |
| Склад → кластер | `warehouse_id` в `/v1/cluster/list` | доказано по идентификатору |
| Остаток → кластер | `warehouse_id` и `cluster_id` | **25 из 25** складов и **19 из 19** кластеров совпали |
| **Продажа → кластер** | **только `warehouse_name`** | **24 из 27 имён**, неоднозначных 0, **3 склада не резолвятся** |

Три склада вне справочника: `РОСТОВ-НА-ДОНУ_РФЦ`, `ЕКАТЕРИНБУРГ_РФЦ_НОВЫЙ`,
`КАЗАНЬ_РФЦ_НОВЫЙ`. На них приходится **52 шт и 60 363 ₽ за 90 дней** — это
около 14 % выручки периода, которую нельзя отнести к кластеру по идентификатору.

Связка `поставка → остаток` **не замыкается по времени**: `arrival_date` пуст
во всех 145 поставках, фактической даты приёмки endpoint не отдаёт.

## Входящие поставки

Заявок в аккаунте **65**, детали получены по 50 последним.
Глубина истории: **2025-07-22 … 2026-09-03**, больше года.

Статусы заявок: `COMPLETED` 37, `CANCELLED` 12, `DATA_FILLING` 1.
Поставок внутри заявок 145: `COMPLETED` 52, `CANCELLED` 92, `DATA_FILLING` 1.
Все 145 — кросс-док. У всех есть `bundle_id`, то есть товарный состав доступен
через `POST /v1/supply-order/bundle` (не запрашивался, отдельный вызов на поставку).

## Чего нет

1. **`warehouse_id` в продажах.** Главный пробел. Атрибуция продаж к кластеру
   держится на совпадении текстового имени.
2. **Фактическая дата приёмки.** `arrival_date` = `null` везде.
3. **История остатков.** Только снимок 2026-08-31, ретроспективы не существует.
4. **Товарный состав поставок.** Доступен, но требует вызова на каждый `bundle_id`.
5. **Справочник кластеров в BigQuery.** Получен из API, но таблицы под него нет.
