# Финансовый периметр рекламы EVETIS на Ozon

Составлено 2026-08-31 по факту вызовов, не по предположениям.
**Маржа и целевой ДРР здесь не пересчитываются** — сначала периметр, потом экономика.

## Разделение расходов

| Метрика | Что входит | Источник | Статус на 2026-08-31 |
| --- | --- | --- | --- |
| `cpc_spend` | 15 кампаний `advObjectType=SKU`, оплата за клик | Performance API `statistics/expense`, колонка «Расход» | **подтверждён**: 6 154,10 ₽ за неделю 24–30 авг по 7 проверенным кампаниям |
| `search_promo_spend` | кампания 14503166, `SEARCH_PROMO`, оплата за заказ (CPO) | там же | **подтверждён**: 238,40 ₽ за август (2 списания по 119,20) |
| `referral_vk_spend` | 20 кампаний `REF_VK` | там же | **ноль по Performance API** за 01–30 авг. Источник списания не найден |
| `referral_blogger_spend` | 5 кампаний `REF_BLOGGER` | там же | **ноль по Performance API** за 01–30 авг. Источник списания не найден |
| `other_promo_spend` | `BANNER` (FINISHED), `ALL_SKU_PROMO` (INACTIVE) | там же | ноль, кампании не работают |
| `total_marketing_spend` | сумма всех перечисленных | — | = `cpc_spend` + `search_promo_spend` + остальные, когда будут доказаны |

Дополнительные колонки, которые нельзя терять: `statistics/expense` возвращает
**«Расход»**, **«Расход бонусов»** и **«Расход с абонентского счета»** раздельно.
По проверенным кампаниям бонусы и абонентский счёт = 0, но в модели их надо хранить отдельно,
иначе при первом же использовании бонусов расход будет посчитан неверно.

## Два ДРР, которые нельзя смешивать

- `drr_cpc` = `cpc_spend` / выручка — привычный показатель, сравнимый с историей.
- `drr_total_marketing` = `total_marketing_spend` / выручка — то, с чем надо сравнивать потолок маржи.

На сегодня разрыв между ними мал: `search_promo_spend` 238,40 ₽ против недельного CPC порядка
6 000 ₽ по семи кампаниям. Но SEARCH_PROMO работает по CPO и списывает 119,20 ₽ за заказ —
при росте заказов эта статья растёт линейно и в CPC-отчётность не попадает.

## Что ещё не закрыто

`REF_VK` и `REF_BLOGGER` — 25 работающих кампаний с нулевым расходом по Performance API.
В блоке `marketing_actions` из Seller API по нашим товарам видны программы
«Семплинг в Реф. Программе Ozon x VK Adblogger» с бюджетами 5 000, 10 000 и 40 000 ₽
и периодами до 15 октября 2026. Деньги где-то списываются либо не списываются вовсе.

Проверено: в начислениях за 2026-08-28 из 124 типов встретились только
`41 Оплата за клик` (−1 599,00 ₽), `32 Логистика`, `29 Доставка до места выдачи`,
`1 Эквайринг`, `59 Обратная логистика`, `76 Страхование`, `46 Размещение на складах`.
Маркетинговых типов (`33 Marketing`, `54 Promotion`, `19 ExternalPromotion`,
`87 SocialMediaAdvertising`, `3 BrandCommission`) — нет.

Один день не доказывает отсутствие. До вывода нужно проверить начисления за даты
активности семплинга. **До этого `referral_*_spend` считать `NOT_PROVEN`, а не нулём.**

## Контрольная сумма для будущей выгрузки

Сумма `statistics/expense` по всем CPC-кампаниям за 2026-08-28 должна сойтись с этой цифрой.
