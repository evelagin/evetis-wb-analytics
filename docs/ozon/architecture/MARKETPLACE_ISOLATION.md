# Marketplace Isolation — жёсткое архитектурное правило

Зафиксировано владельцем 2026-09-01. Действует на весь домен Ozon и на весь домен WB.

EVETIS Wildberries Analytics и EVETIS Ozon Analytics — **два независимых marketplace domain**.
Они могут жить в одном Git-репозитории и в одном GCP-проекте, но их RAW, STG, MART,
ingestion, финансы, реклама и операционная логика изолированы строго.

## BigQuery namespace

| Домен | Датасеты |
| --- | --- |
| Wildberries | `wb_raw`, `wb_stg` / существующий слой нормализации WB, `wb_mart` |
| Ozon | `ozon_raw`, `ozon_stg`, `ozon_mart` |
| Общее | `evetis_ref` — **только** справочники |

`evetis_ref` разрешён обоим доменам исключительно для:
SKU master, история себестоимости, наборы, маппинг товаров между площадками
и прочие действительно marketplace-независимые справочники.

## Запрещённые зависимости

```
ozon_raw  → wb_*        ЗАПРЕЩЕНО
ozon_stg  → wb_*        ЗАПРЕЩЕНО
ozon_mart → wb_*        ЗАПРЕЩЕНО
wb_raw    → ozon_*      ЗАПРЕЩЕНО
wb_mart   → ozon_*      ЗАПРЕЩЕНО
```

WB-факт нельзя использовать как замену отсутствующего Ozon-факта и наоборот.

**Совпадение товара через общий SKU-маппинг не означает совпадения** цены, комиссии,
заказа, продажи, рекламы, остатка, логистики, возврата или финансовой операции.
Все эти факты всегда принадлежат конкретной площадке.

## Изоляция репозитория

Новый код и документация Ozon — в отдельных namespace:
`sql/ozon/`, `tools/ozon/`, `docs/ozon/`, `pipelines/ozon/`.

Нельзя: переносить Ozon SQL в существующие файлы WB, добавлять Ozon-колонки в витрины WB,
менять бизнес-семантику WB ради Ozon.

## Кросс-маркетплейсная аналитика

Допускается только как отдельный будущий слой поверх обоих доменов:

```
wb_mart   ──┐
            ├── cross-marketplace executive layer
ozon_mart ──┘
```

Этот слой не входит ни в WB, ни в Ozon домен и не меняет их source-of-truth факты.
**На текущем этапе кросс-маркетплейсный MART не создаётся.**

## Изоляция записи

В production ingestion предусмотреть разные service identity и IAM-границы:
пайплайн Ozon не должен иметь права записи в датасеты WB и наоборот.
**Пока только проектирование. IAM не менять без отдельного разрешения.**

## Проверка соответствия

Перед завершением любого этапа проектирования Ozon SQL проверять:

1. нет чтения из `wb_raw`;
2. нет чтения из `wb_mart`;
3. исключение — только явно разрешённые общие справочники в `evetis_ref`;
4. нет записи в датасеты WB;
5. факты Ozon имеют собственный marketplace grain и собственные натуральные ключи.

**Любое нарушение — architecture QA FAIL.**

## Имя репозитория

Текущее имя `evetis-wb-analytics` архитектурно ничего не решает и работе не мешает.
Переименование в `evetis-marketplace-analytics` отложено до момента, когда заработает
production-слой Ozon. GitHub сохранит redirect со старого адреса, локальный remote
обновляется отдельно. Это косметика, не блокер.
