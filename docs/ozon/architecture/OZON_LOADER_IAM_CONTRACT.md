# IAM-контракт загрузчика Ozon

Дата: 2026-09-01. Принцип: **отдельная identity домена Ozon, минимальные права,
никакого доступа на запись в датасеты WB.**

## Identity

| | |
| --- | --- |
| Service account | `sa-ozon-ingestion@project-fa311fc0-4d87-4781-986.iam.gserviceaccount.com` |
| Отображаемое имя | `Ozon loaders runtime` |
| Соответствие конвенции проекта | да: WB использует `sa-loaders-prod` / `sa-loaders-shadow`, здесь домен вынесен в имя |

Отдельная identity нужна не для красоты: у `sa-loaders-prod` есть права на запись
в `wb_raw`. Если загрузчик Ozon поедет под ней, правило изоляции будет нарушено
на уровне IAM, а не только на уровне SQL.

## Выдаваемые права

| Роль | Область | Зачем |
| --- | --- | --- |
| `roles/bigquery.jobUser` | проект | запускать load job. Права на данные это не даёт |
| `roles/bigquery.dataEditor` | **датасет `ozon_raw`** | писать в таблицы домена Ozon |
| `roles/bigquery.dataViewer` | **датасет `evetis_ref`** | читать общие справочники |
| `roles/storage.objectViewer` | **бакет staging** | читать подготовленные JSONL |

Все привязки к данным — **на уровне ресурса**, не проекта.

## Явно НЕ выдаётся

```
roles/owner, roles/editor            широкие роли — запрещены
WRITE в wb_raw                       нарушило бы изоляцию доменов
WRITE в wb_mart                      то же
WRITE в ozon_stg, ozon_mart          на этом этапе загрузчик туда не пишет
доступ к значениям секретов Ozon     на историческом bootstrap API не вызывается
```

Права на `ozon_stg` и `ozon_mart` не выдаются сознательно: Stage 3.1B грузит только
`ozon_raw`. Когда появится слой нормализации, права расширятся отдельным решением.

Доступ к секретам (`EVETIS_OZON_API_KEY`, `EVETIS_OZON_PERFORMANCE_*`) не выдаётся,
потому что исторический bootstrap читает готовые файлы из GCS и в Ozon API не ходит.
Это понадобится позже, на runtime-загрузчике из API.

## Staging-бакет

| | |
| --- | --- |
| Имя | `evetis-ozon-staging-37074083763` |
| Регион | `europe-west1` |
| Доступ | uniform bucket-level access |
| Публичный доступ | запрещён |
| Назначение | только подготовленные canonical JSONL для исторического bootstrap |

Отдельный бакет, а не существующий `evetis-wb-tfstate-*`: тот хранит состояние
Terraform, смешивать с данными нельзя.

## Проверка изоляции после выдачи прав

1. `sa-ozon-ingestion` не имеет ни одной роли на `wb_raw` и `wb_mart`.
2. Роли на данные привязаны к датасету, а не к проекту.
3. Ни одна существующая привязка WB не изменена.
4. Широких ролей на проект нет.
