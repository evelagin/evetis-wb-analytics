# Ozon: что воронка отдаёт на самом деле (проба API)

Дата: 2026-09-21 · Gate 6A · Метод: живые запросы боевым ключом продавца, только чтение.
Секреты не печатались и на диск не писались.

## Вывод одной строкой

**Корзину по SKU × день получить нельзя: метрика снята с API.** Это не подписка и не права —
Ozon отвечает `400 deprecated metrics used` на действующем ключе.

## Что показала проба

| метрика | HTTP | ответ |
| --- | --- | --- |
| `hits_view`, `hits_view_search`, `hits_view_pdp` | 400 | `deprecated metrics used` |
| `hits_tocart`, `hits_tocart_search`, `hits_tocart_pdp` | 400 | `deprecated metrics used` |
| `conv_tocart`, `conv_tocart_search`, `conv_tocart_pdp` | 400 | `deprecated metrics used` |
| `session_view`, `session_view_search`, `session_view_pdp` | 400 | `deprecated metrics used` |
| `cancellations`, `returns`, `delivered_units`, `position_category` | 400 | `deprecated metrics used` |
| **`ordered_units`** | **200** | доступна |
| **`revenue`** | **200** | доступна |
| `unknown_metric_xyz` (контроль) | 400 | `Request validation error: invalid ... Metrics` |

Контрольный запрос — важная часть доказательства: API **различает** «метрика снята» и «метрики
не существует». `hits_tocart` попадает в первую категорию, то есть Ozon её знает и сознательно
вывел из обращения.

Ещё одна ловушка: при запросе нескольких метрик сразу снятые **молча отбрасываются** — приходит
`200` и меньше колонок, чем просили. Запрос `[hits_view, hits_tocart, conv_tocart, ordered_units,
revenue]` вернул две метрики вместо пяти. Поэтому пробовать надо по одной.

## Другие эндпоинты

`/v2/analytics/data`, `/v3/analytics/data`, `/v1/analytics/item_turnover`,
`/v1/analytics/manage/stocks`, `/v1/product/info/limit` — **404**. Единственный живой
аналитический эндпоинт — `POST /v1/analytics/data`; `/v1/analytics/turnover/stocks` отвечает 200,
но это оборачиваемость остатков, а не воронка.

## Глубина истории

Для доступных метрик окно около трёх месяцев: запросы за 07, 08 и 09.2026 отвечают `200`,
за 06.2026 и раньше — `400` с текстом `date_to must be greater than date_from`. Текст вводит
в заблуждение: даты корректны, это граница хранения. Для корзины вопрос всё равно не стоит —
метрики нет вовсе.

## Premium — это НЕ про воронку

Две разные вещи, и смешивать их нельзя:

| | что это | статус |
| --- | --- | --- |
| Premium как расход | подписка 9 990 ₽ в мае 2026, июнь–август отсутствует | `ACCOUNT_LEVEL_EXPENSE`, в юнит-экономику SKU не входит |
| Premium как доступ к аналитике | гипотеза, что подписка открывает воронку | **опровергнута**: отказ приходит с кодом «метрика снята», а не «нет прав» |

Если бы дело было в подписке, ответ был бы про доступ. Он про депрекацию — то есть метрики нет
ни у кого, независимо от Premium.

## Что это значит для листа

Колонка «Положили в корзину» **сохраняется** и остаётся самостоятельным KPI воронки. Она не
переиспользуется под расходы (под «Прочие прямые» заведена отдельная 25-я колонка).

Политика значений:

| ситуация | в листе |
| --- | --- |
| наблюдалось 0 | `0` |
| наблюдалось > 0 | значение |
| источник недоступен (метрика снята) | **пусто** |
| дата вне окна хранения | **пусто** |

`0` и «недоступно» не смешиваются никогда.

## Уже накопленные значения нельзя стирать

В боевом листе колонка **не пустая**: например, в апрельских блоках по 28 заполненных суток
(14, 21, 25, 16, …). Это настоящие наблюдения, снятые когда метрика ещё работала.

Здесь есть неочевидная опасность. Сетка значений писателя заполняется пустыми строками, и любая
колонка, которую никто явно не выставил, была бы **стёрта записью**. Поэтому значения корзины
читаются из листа и проносятся через запись без изменений (`cartBy` в `composeMonth`) — ровно так
же, как доказанные снимки остатка. Новых значений взять неоткуда, но и терять старые нельзя.

Когда/если Ozon вернёт метрику, заполнение колонки не потребует новой миграции геометрии:
место под неё уже есть, меняется только источник.
