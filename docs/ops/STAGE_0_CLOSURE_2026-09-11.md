## 5. Governance blocker — production опережает `main`

| Что | Где в production | В `main` |
|---|---|---|
| Ресурсы загрузчика воронки (`wb_funnel_loader.tf`, изменения `secrets.tf`) | применены из ветки `feat/unitka-*`; планировщик `wb-funnel-prod` PAUSED | нет |
| Образ загрузчиков (`wb-mart-prod` и др.) | собран из `bbb4ec0` (`feat/unitka-2.0-funnel-reports-token`), деплой `deploy-prod` 11.09 06:48Z из ветки; до 10.09 был `12a62ca` из `main` | `bbb4ec0` не в `main` |

Разница кода аддитивна (новый загрузчик воронки + опциональные параметры конфига с умолчаниями), логика витрины и
общий рантайм не менялись — поэтому поведение витрины совпадает с `main`. Проблема — происхождение.

**Правило до слияния:**
- **обычный `terraform apply` из `main` запрещён** — полный план из `main` предложит удалить ресурсы воронки;
- **`deploy-prod` из `main` запрещён** — откатит образ и уберёт загрузчик воронки;
- допустимы только целевые apply с просмотренным планом.

Снимается, когда работа по воронке слита в `main` через PR и полный план из `main` показывает только известный
косметический дрейф (`client = gcloud` у `wb_mart_prod` / `wb_stocks_prod`, `retry_config` у `wb_funnel_prod`).
