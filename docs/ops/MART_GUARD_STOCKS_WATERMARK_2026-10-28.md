# Дефект: guard `wb-mart-prod` не пересобирает витрину после позднего снимка остатков (28.10.2026)

Статус: **проект исправления, НЕ развёрнуто.** Ветка `fix/mart-guard-stocks-watermark`.

## Что обнаружено
28.10 снимок остатков восстановлен в 17:33 UTC (ACK A1). Слоты `wb-mart-prod` 12:00 и 16:00 МСК вышли с
`guard_skip`, `reason: COMPLETE`. Guard (LOADER_RUNS, период D-1) пропускает слот, если сутки уже собраны на той же
версии источника, а версия источника (`fin:v2`) — отпечаток только финансов (`V_WB_FINANCE_SEMANTIC`). Поздний снимок
остатков (восстановление, догон Apps Script из #386, ручной перезапуск) версию не меняет — `FACT_STOCKS_SNAPSHOT`
ждёт следующих суток.

## Исправление (минимальное)
`cloud/src/loaders/mart/watermark.ts`: версия источника витрины = `fin:v2:…|stk:v1:…`. `stk:v1` — SHA256 строк выбора
снимков, из которых `sp_bootstrap_facts` строит `FACT_STOCKS_SNAPSHOT` (COMPLETE, по одному на `period_to`, последний
по `started_at`; выбор дословно как в процедуре — тест сверяет с `sql/mart/pr_mart1_facts.sql`). Отказ любого зонда —
отказ версии целиком: сборка не пропускается (как сейчас у финансов). SQL процедуры, схемы, расписание не меняются.

## Проверки
- Тесты: `cloud/test/mart_watermark_stocks.test.ts` (8) + прежние тесты guard/watermark; весь cloud 1 955 passed, typecheck, lint.
- Живой read-only прогон SQL отпечатка 28.10: без восстановленного манифеста `stk:v1:100:59c59e6f…`, с ним
  `stk:v1:101:db78eaa7…` — дневной слот пересобрал бы витрину.
- Цена зонда: журнал снимков ~100 строк, < 1 МБ.

## Эффект выпуска
- Первый запуск после выпуска пересоберёт витрину один раз (формат версии сменился) — штатно, как при переходе на fin:v2.
- Новый суточный снимок приходит в 06:23 МСК, до первого слота 07:00 МСК, — лишних сборок в сутки нет. Лишняя сборка
  будет только если снимок пришёл после слота, это и есть цель исправления.

## Выпуск (только по OWNER ACK)
Слияние → `deploy-shadow` (shadow-задания на новом образе) → `deploy-prod` для `wb-mart-prod` с digest из сводки
deploy-shadow. Приёмка: первый слот — `guard_acquired` с `rebuildReason`/`watermarkAdvanced`, следующий слот без
изменений — `guard_skip`; `sourceWatermark` в журнале вида `fin:v2:…|stk:v1:…`. Откат — предыдущий digest `wb-mart-prod`.
