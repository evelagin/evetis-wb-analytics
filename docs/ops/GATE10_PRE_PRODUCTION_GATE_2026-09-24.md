## 3. Находка, которая касается production до Gate 10

🔴 **Накопление правил УФ в уже развёрнутом писателе Ozon начнётся 01.10.2026.**
Число правил движка = 43 + 23 × число секций (22 блока). Сейчас секций 17 → 434 — это
совпадает с `OZON_UNITKA_EXISTING_CF_RULES = "434"` в `infra/terraform/ozon_unitka.tf`.
Когда писатель создаст секцию октября, он поставит 457 правил, а снимет по-прежнему 434:
каждый следующий прогон будет оставлять 23 лишних правила. Экономику это не меняет
(УФ — только вид), но лист тяжелеет с каждым прогоном.

Варианты (решение владельца):
1. вывести Gate 10 до 01.10 — писатель снимает реальный префикс движка;
2. если Gate 10 не успевает: в день появления октября поднять `OZON_UNITKA_EXISTING_CF_RULES`
   до 457 целевым apply (хрупко: значение надо менять каждый месяц);
3. принять накопление и почистить лист после вывода Gate 10 (самовосстановление доказано
   на копии: 434 → 435 → 435).

## 4. Предлагаемые production-мутации (выполнять только по разрешению, по порядку)

**Этап 0 — только чтение, непосредственно перед этапом 2.**
Live readback: `ZZ_CONFIG!A29:B34` пусты (коллизий нет); значения `B2` и `B3`
(`B3` не трогается); именованные диапазоны книги (`OZON_LAST_CLOSED_DATE` ещё нет);
геометрия листа Ozon (колонки, число правил УФ, зеркало); якорь WB. Отпечаток значений
листа Ozon — сохранить.

**Этап 1 — развёртывание кода (без изменения книги).**
1. Ревью и слияние PR в `main`.
2. `deploy-shadow` соберёт образ из merge-коммита → digest.
3. `deploy-prod` с этим digest и SHA (обновляет все prod-job общего образа, в том числе
   `unitka-engine-prod` и `ozon-unitka-prod`).
4. После этого: WB — AUTO-LCD (блока цикла нет → AUTO), B2 коммитится после проверки;
   Ozon — авторитет **LEGACY** (`OZON_UNITKA_LCD_CELL = "ZZ_CONFIG!B2"`): читает B2,
   собственный LCD не пишет; работают ёмкость и снятие реального префикса УФ.
   Итоговое состояние книги WB не отличается от нынешнего (раздел 2).

**Этап 2 — миграция LCD Ozon (изменение книги, в окне между прогонами Ozon).**
1. Засеять `ZZ_CONFIG!A29:B34` (6 строк; `B30` = текущее значение `B2`).
2. Создать именованный диапазон `OZON_LAST_CLOSED_DATE` → `ZZ_CONFIG!B30`.
3. Переписать 32 967 формул листа Ozon модулем `ozon/lcd_migration.ts` (`verifyPlan` = ok).
4. Сверить отпечаток значений до/после — обязан совпасть.
5. Целевой apply `ozon_unitka.tf`: `OZON_UNITKA_LCD_CELL = "OZON_LAST_CLOSED_DATE"`.
   Константы `OZON_UNITKA_TAIL_FIRST_COLUMN`, `OZON_UNITKA_BLOCK_SLOTS`,
   `OZON_UNITKA_LCD_REF`, `OZON_UNITKA_EXISTING_CF_RULES` после Gate 10 не авторитетны
   (писатель выводит их из листа и только предупреждает о расхождении).
6. Ручной запуск `ozon-unitka-prod` и проверка: PRE/POST_COMMIT PASS, `LCD_COMMITTED`
   или `LCD_NOT_ADVANCED`, лист WB не изменился.

  `sha256:70fd2450544e69e3b743ab4e85e417682ff9ba88ef87e0c07f59baf50fae133d`.

## 5. Ранбук эксплуатации после вывода

| событие | что значит | что делать |
|---|---|---|
| `LCD_CANDIDATE` | кандидат вычислен | ничего |
| `LCD_COMMITTED` | день закрыт после записи и проверки | ничего |
| `LCD_REVERTED` | проверка после коммита не прошла, свой коммит откачен | разобрать причину в `qa_json` |
| `LCD_LEGACY_READONLY` | Ozon на авторитете B2 (до этапа 2) | ожидаемо до миграции |
| `LCD_NOT_ADVANCED` | нечего закрывать (источник не готов или уже закрыто) | WB: удержание дольше `UNITKA_MAX_LAG_DAYS` (2) — отдельная ошибка `LCD_HELD_BY_COVERAGE_GAP` |
| `LCD_COMMIT_CONFLICT` | LCD изменили во время прогона | выяснить, кто менял; прогон ничего не перетёр |
| `LCD_WRITE_FAILED` | данные опубликованы, LCD не лёг | следующий прогон коммитит один раз (WB — без повторной записи данных; Ozon переписывает своё окно как обычно) |
| `MANUAL_OVERRIDE_ACTIVE` | ручной режим включён | вернуть `AUTO`, когда причина устранена |
| `NEW_MONTH_CREATED` | секция месяца создана | манифест отката — в `unitka_month_prep_rollback_manifest` |
| `NEW_SKU_ACTIVATED` / `CAPACITY_EXPANDED` | новый SKU / вставлен блок | проверить подпись блока |
| `NO_SAFE_EXPANSION_PATH` | ёмкость не расширить безопасно | решение владельца |
| `INTEGRITY_FAILED` | сбой проверки целостности | коммита нет, разобрать причину |

Ручной режим WB: `ZZ_CONFIG!B31 = MANUAL`, `B32 = дата`. Ozon: `B33 = MANUAL`, `B34 = дата`.
Невалидная дата, дата в будущем относительно источника или откат назад — отказ без записи.
Утилита `unitka-month-prep` остаётся только для администрирования и восстановления.
