Семантика: журнал в **физических** единицах; карточки и наборы раскладываются по BOM до записи; бакет =
состояние × место × канал × контейнер × документ, у каждого состояния своя обязательная форма; переходы —
по белому списку; исправление — только сторно (зеркальное движение, один раз, сторно сторно запрещено);
`READY_TO_SUPPLY` Ozon = `RESERVED/OZON` на ФФ, не «в пути»; запас площадок и «в пути» — только из API,
в журнал не пишутся; FBO-наборы (`ASSEMBLED`, под отгрузку) и FBS-наборы (`FBS_READY`) различимы;
мощности наборов не складываются (`V_CT_BUNDLE_CAPACITY` показывает общие компоненты).
Каждая пишущая процедура: идемпотентна по `request_id`, одна транзакция со строкой-замком, отказ =
`ROLLBACK` + строка `REJECTED` в журнале запросов. Отказ, если: не хватает запаса, данные API старше
`max_api_age_hours` (30 ч), двойной резерв документа площадки, неполный BOM, бакет ушёл бы в минус,
запись владельца выключена.

`REF_SKU_LOGISTICS` создана **пустой**: коробка, вес, минимальная партия, кратность, дни покрытия по каналам,
страховой запас, срок поставки, FBS-резерв, `effective_from/to` — значения даёт владелец, не выводятся.
