# Stage C2 · EVETIS OPERATIONS — автоматическое обновление (Google Sheets + Apps Script + BigQuery)

Дата: 2026-09-14. Статус: реализовано, проверено на временной копии и развёрнуто в рабочую книгу «EVETIS OPERATIONS» 14.09.2026 (§14).

## 1. Архитектура

```
BigQuery evetis_ops (источник правды и расчёт, C1: V_OPS_*)
  └─ контракт листов V_OPS_SHEET_* (ops_09_sheet_contract.sql, только чтение, итоги и ключи)
       └─ Apps Script, привязанный к книге (apps-script/evetis_operations) — только синхронизация
            └─ существующие диапазоны листов 01–05 и DATA (UI C1.2)
                 └─ _OPS_STATE (скрытый лист) — решения владельца «Одобрено владельцем»
```

- Расчёт поставок остаётся в BigQuery (C1). C2 не меняет ledger, правила пополнения, 45-дневную логику, сроки,
  округление, ворота затоваривания, BOM, распределение ФФ, количества рекомендаций и логистику.
- Скрипт BigQuery только читает. Запись идёт только в книгу.
- Решение владельца — состояние интерфейса, а не команда на отгрузку: в журнал, BigQuery и API площадок ничего не пишется.

## 4. Контракт раскладки (маркеры)

У каждого листа 01–05 и DATA есть скрытая защищённая (с предупреждением) служебная колонка:
01 → I, 02 → R, 03 → O, 04 → N, 05 → Z, DATA → A. В ней у каждой строки раскладки маркер:

| Маркер | Смысл |
|---|---|
| `@L:C2L1` | первая строка, версия раскладки |
| `@S` | статичная строка (не трогается) |
| `@V:<блок>` | строка со сгенерированным текстом (статус, подзаголовок) |
| `@B:<блок>` | полоса блока (текст и заметка генерируются) |
| `@H:<блок>` | шапка (не трогается) |
| `@R:<блок>:<ключ>` | строка данных; в блоках отгрузки ключ = `business_key#отпечаток` |
| `@E:<блок>` | пустой блок — одна строка «Нет позиций» |
| `@T:<блок>` | ИТОГО |
| `@END` | конец раскладки |

- Блоки ищутся только по маркерам. Число строк меняется только внутри блоков данных: новые строки получают формат и
  высоту первой строки блока, объединения ячеек блока (ПРОВЕРИТЬ: C:D, E:H) создаются заново.
- Ширины колонок, закрепление, заметки шапок, объединения шапок, скрытость листов и оформление колонки владельца не меняются.
- Любое нарушение контракта (нет маркера, лишняя строка, другой порядок, повтор ключа) → FAIL CLOSED, лист не перестраивается.
- Установка (`opsSetup`) ищет блоки C1.2 по видимым текстам один раз, со строгой сверкой всей раскладки; при любом
  расхождении — ни одной записи. Установка останавливается, если в «Одобрено владельцем» уже есть значения.

## 5. Ключ и отпечаток рекомендации

- **business_key** = `SUPPLY_SHIP|<channel>|<card_sku>` — зерно плана C1 (канал × карточка). Не номер строки и не
  название товара. Способ отгрузки у канала один (`REF_CHANNEL_SHIPPING.is_planning_default`) и входит в отпечаток.
- **rec_fingerprint** = первые 16 символов SHA-256 от
  `business_key | shipping_method | status_code | rule | rec_final | rec_physical_units | ворота`,
  где ворота — сработавшие флаги затоваривания (O), срока годности (E), неподтверждённой приёмки (A), нехватки ФФ (F).
- Не входят: даты (сдвиг дня), название товара, время расчёта, уверенность в спросе, номер строки.
- I24 проверяет, что отпечаток — функция только этих полей.

## 6. Решение владельца (`_OPS_STATE`)

Скрытый защищённый (с предупреждением) лист. Таблица A:N — состояние по ключу, P:V — журнал событий.

| Колонка | Смысл |
|---|---|
| business_key | канонический ключ |
| current_fingerprint / current_block / current_rec_final | что показано сейчас |
| approved_fingerprint / approved_qty / approved_at | действующее решение |
| approval_status | NONE · APPROVED · REAPPROVAL_REQUIRED · INACTIVE |
| last_seen_at | последняя запись, в которой ключ был в выборке |
| previous_approved_qty / _fingerprint / _at | прежнее решение (аудит) |
| invalidated_at / invalidation_reason | FINGERPRINT_CHANGED · LEFT_SHIP_BLOCK · KEY_ABSENT · CLEARED_BY_OWNER |

Журнал событий: APPROVED, REAPPROVED, INVALIDATED, INACTIVE, RETURNED, CLEARED (источник ONEDIT или REFRESH).

**Правила (политика тестов 11–13):**
1. Ввод числа в «Одобрено владельцем» (installable onEdit) → APPROVED с отпечатком строки, которую владелец видел.
2. Обновление: отпечаток тот же и строка в блоке отгрузки → решение живо (показывается количество).
3. Отпечаток изменился → решение недействительно навсегда: прежнее — в previous_*, статус REAPPROVAL_REQUIRED.
4. Строка ушла из отгрузки (рекомендация 0 / ЖДАТЬ / ПРОВЕРИТЬ) или исчезла → INACTIVE; вернулась — REAPPROVAL_REQUIRED,
   даже если количество и отпечаток совпадают со старым решением.
5. Старое решение само не оживает (100 → 120 → 100 требует нового подтверждения).
6. Очистка ячейки владельцем → NONE, прежнее значение сохраняется.
7. Неверный ввод (не целое ≥ 0) не принимается: сообщение, в ячейке — текущее состояние.

**Отображение в колонке D** (ширину C1.2 менять нельзя): APPROVED — количество; REAPPROVAL_REQUIRED — «ПЕРЕСОГЛ. N»
красным (9 pt, по левому краю), полный текст «ПЕРЕСОГЛАСОВАТЬ · ранее: N (одобрено …)» — в заметке ячейки.

## 7. Обновление

1. `LockService` (ожидание 30 с) → иначе `SKIPPED_LOCKED`.
2. Все 11 запросов (задания запускаются параллельно) → типы значений по схеме BigQuery.
3. Проверки до первой записи (FAIL CLOSED): схема (обязательные колонки), число строк, уникальность ключей и порядка,
   канонический ключ, формат отпечатка, согласованность блоков, один день во всех выборках, сверки R1–R6, контракт
   раскладки всех листов, заголовки `_OPS_STATE`, машина состояний, полная отрисовка в памяти.
4. Данные не изменились и событий нет → пишется только статус (`OK_NO_CHANGE`).
5. Иначе: флаг `OPS_WRITE_IN_PROGRESS` → `_OPS_STATE` → листы 01…05, DATA → снимок в Script Properties → флаг снят.
6. Ошибка до записи: в книге меняется только статус (строка 2 листа 01 и блок «ОБНОВЛЕНИЕ ДАННЫХ» на 04);
   на экране — последний проверенный снимок.
7. Ошибка во время записи: следующий запуск перерисовывает сгенерированные диапазоны из свежих данных, а если их
   получить нельзя — из последнего успешного снимка (`RESTORED_LAST_GOOD`). `_OPS_STATE` не откатывается.

Статусы запуска: OK · OK_NO_CHANGE · WARNING · WARNING_NO_CHANGE · FAILED_CLOSED · WRITE_FAILED · RESTORED_LAST_GOOD · SKIPPED_LOCKED.

**Свежесть:** источник устарел, если срез старше `OPS_CONFIG.max_api_age_hours` (30 ч) — ВНИМАНИЕ, не блокирует запись.

## 8. Режимы запуска

| Режим | Что делает |
|---|---|
| `onOpen` (простой триггер) | меню «EVETIS OPERATIONS», всплывающее предупреждение при ошибке или если успешного обновления не было > 2 ч. BigQuery не вызывает |
| Меню → Обновить данные | принудительное обновление |
| Меню → Проверить статус | статус, время, 8 последних запусков |
| Меню → Включить / Выключить автообновление | ежечасный триггер `opsTriggerRefresh` |
| Installable onEdit `opsOnEditInstalled` | запись решения владельца в `_OPS_STATE` |
| `opsSetup` (из редактора, один раз) | установка раскладки, триггер onEdit, первое обновление |

Каденс: ежечасно. Источники меняются утром (остатки WB ~06:23, заказы Ozon ~06:36, остатки Ozon ~07:00, заказы WB
~07:32 МСК), плюс смена даты в полночь и движения журнала ФФ. Стоимость ~10–15 МБ сканирования на запуск.
Квота Apps Script личного аккаунта: ~90 мин работы триггеров в сутки; запуск без изменений — секунды, с записью ~20–80 с.

## 10. Развёртывание в рабочую книгу

1. Экспорт книги (резервная копия) и проверка `ops_c2_sheet_verify.py same` с экспортом до тестов.
2. Расширения → Apps Script → проект «EVETIS OPERATIONS · C2» (привязан к книге).
3. Настройки проекта: показать `appsscript.json`; вставить манифест; в файл кода (`Код.gs`) — сборка
   OpsConfig → OpsCore → OpsSheetIO → OpsInstall → OpsMain **без OpsTests.gs**; сверить SHA-256 сборки.
4. Перед запуском ещё раз `same` с резервной копией (привязка проекта меняет время изменения файла, но не содержимое).
5. Выполнить `opsSetup` → окно разрешений Google (подтверждает владелец) → установка раскладки, `_OPS_STATE`,
   триггер onEdit, первое обновление.
6. Проверка: I24; `ops_c2_sheet_verify.py verify <экспорт> --before <резервная копия>`; контрольные суммы журнала
   `evetis_ops`; типы заданий BigQuery (только SELECT к `V_OPS_SHEET_*`); визуальная проверка всех листов
   (скрытые DATA и `_OPS_STATE` — только чтение через `gviz/tq?tqx=out:html&sheet=…`, не раскрывать).
7. Безопасные смоук-тесты: Меню → Обновить данные; `opsTriggerRefresh` из редактора (путь триггера, без изменений);
   Меню → Проверить статус. Имитация сбоев и правка «Одобрено владельцем» в рабочей книге не выполняются.
8. Меню → Включить автообновление; дождаться выполнения типа «Триггер по времени» в журнале выполнений.

В выпадающем списке функций редактора выбор иногда не фиксируется: перед «Выполнить» проверить выбранную функцию.
Запуск `onOpen` из редактора падает на `SpreadsheetApp.getUi()` (контекст без интерфейса) — это безвредно, ничего не пишет.

## 11. Восстановление

| Ситуация | Действие |
|---|---|
| ОШИБКА в статусе, данные на экране старые | Меню → Проверить статус; причина в журнале. Данные BigQuery → исправить источник; следующий запуск восстановит |
