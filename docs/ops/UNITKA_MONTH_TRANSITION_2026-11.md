# Переход месяца октябрь → ноябрь 2026: WB и Ozon Юнитка

Статус: проверено чтением и изолированными тестами 20–21.10.2026. Production-ноябрь заранее не создаётся.

Доказательства и холостой план:
- `evetis-manifests/unitka-ops-acceptance-2026-10-20/D_month`;
- тест `cloud/test/unitka_month_transition_nov.test.ts`.

## 1. Что произойдёт само (ручная подготовка не нужна)

С Gate 10 (24.09.2026) месяц создаёт суточный прогон.

- **WB.** `unitka-engine-prod` вызывает `ensureWbMonthSection` (cloud/src/loaders/unitka/wb_lifecycle.ts). Тот же генератор, что у `unitka-month-prep`. Отпечаток манифеста не требуется — решение владельца.
- **Ozon.** `ozon-unitka-prod` создаёт месяц сам: так 02.10 был создан октябрь (запуск vsp4n).

| Дата, UTC | WB (unitka-engine-prod) | Ozon (ozon-unitka-prod) |
|---|---|---|
| 01.11 07:00 | закрывает 31.10 (строка 801), ноябрь не создаёт | закрывает 31.10; 1-е число — глубокая сверка 120 суток |
| 02.11 07:00 | создаёт ноябрь одним batchUpdate. До записи пишет `unitka_month_prep_rollback_manifest`. Затем пишет 01.11 в строку 806 и событие `NEW_MONTH_CREATED`, после этого коммитит `LCD_COMMITTED` (B2 = 01.11) | создаёт ноябрь (строки 674…707) и коммитит B30 = 01.11 |
| 02.11 09:30 | резервный прогон: секция уже есть, ничего не создаёт | — |
| 02.11 10:00 / 10:20 | WB P&L и Ozon P&L подхватывают ноябрь (новая строка месяца) | |

**Холостой план ноября WB на живой книге** (20.10, только GET):
- `PLAN_CREATE`, отказов нет;
- секция 804..837, 25 блоков, колонки не вставляются, 2 122 запроса.

**Ozon:** 22 блока = 22 слота, все offer уже в листе.

## 2. Что может остановить создание (все отказы — до записи, 0 изменений листа)

| Код | Причина | Как избежать до 02.11 |
|---|---|---|
| `CHAIN_GAP` | SKU выведен из `REF_SKU_MASTER` и оставил дыру в цепочке блоков | не деактивировать WB SKU до 02.11 |
| `COGS_MISSING` / `COGS_STALE` / `COGS_UNAVAILABLE` | у нового SKU нет опубликованной канонической себестоимости | новый SKU включать только с каноном COGS |
| `TEMPLATE_MISMATCH` | формулы октября изменены вручную | не править формулы октября |
| `MONTH_PREP_NO_PREDECESSOR`, `MONTH_SECTION_AMBIGUOUS`, `MONTH_SECTION_CHAIN_TOO_LONG` | нет секции октября, она задвоена или LCD перескочил больше месяцев, чем допустимо | не вставлять и не копировать секции вручную |
| `MONTH_PREP_VERIFY_FAILED` | после записи секция не прошла контракт | — (откат по манифесту, §4) |

**Последствие отказа:**
- LCD остаётся 31.10, лист и P&L не получают ноябрь;
- деньги не искажаются;
- следующий плановый прогон попробует снова.

## 3. Как владелец узнает

- **Отказ создания** — письмо «ЮНИТКА/P&L: прогон упал» (код из §2) — политика `unitka_writers_failed`.
- **LCD не сдвинулся 27 ч / 26 ч** — письмо heartbeat «UNITKA WB/Ozon: LCD не сдвигался».
- До включения новых политик действующие политики UNITKA Engine / OZON Unitka тоже ловят ERROR с кодом.
- `NEXT_MONTH_SECTION_MISSING` (WARNING 27.10…01.11) — **не сигнал**: до 02.11 секции нет всегда, это ожидаемо.

**Проверка 02.11 после 10:10 МСК (07:10Z):**
- в журналах: `NEW_MONTH_CREATED` 2026-11 и `LCD_COMMITTED` для WB и Ozon;
- ZZ_CONFIG: B2 = B30 = 01.11.2026;
- WB_Юнит_2025 — ноябрь с A804, OZON_Юнит_2025 — с A674;
- после 13:25 МСК — оба P&L опубликованы.
- Сохранить `digest` из `unitka_month_prep_rollback_manifest` (WB) — он нужен для отката.

## 4. Резерв при фактическом отказе

1. **Ничего не перезапускать вслепую.** По коду отказа (§2) устранить причину: вернуть SKU, опубликовать COGS, восстановить формулу октября. Следующий плановый прогон создаст месяц сам.
2. **Если ждать нельзя** — ручной путь WB, тот же планировщик и те же отказы, только по OWNER ACK:
   ```
   gcloud run jobs execute unitka-engine-prod --region europe-west1 --args=unitka-month-prep --wait \
     --update-env-vars=DRY_RUN=1,UNITKA_MONTH_PREP_TARGET=2026-11                        # план, 0 записей
   gcloud run jobs execute unitka-engine-prod --region europe-west1 --args=unitka-month-prep --wait \
     --update-env-vars=UNITKA_MONTH_PREP_TARGET=2026-11,UNITKA_MONTH_PREP_WRITE=1,UNITKA_MONTH_PREP_MANIFEST_DIGEST=<digest плана>
   ```
   - Не запускать в часе 12 МСК: это слот резерва 09:30Z, и guard его заглушит.
3. **Ошибочно созданная секция** — откат `unitka-month-rollback` по `manifest_b64` (docs/UNITKA_ENGINE_V1_RUNBOOK.md §5c), только по ACK.
4. **Ozon:** отдельного ручного пути создания нет. Устранить причину по коду отказа `ozon-unitka-prod`; следующий плановый прогон 07:00Z создаст месяц.
