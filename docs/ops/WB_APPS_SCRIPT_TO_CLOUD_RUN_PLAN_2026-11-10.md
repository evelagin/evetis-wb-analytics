# Перенос загрузки WB из Apps Script в Cloud Run — план (10.11.2026)

Статус: **ПЛАН, ничего не исполняется.** Каждый этап с эффектом на production выполняется только
по отдельному OWNER ACK. Для Terraform сначала показывается `plan`, затем `apply`.

Основание:
- инвентаризация 21.10;
- инцидент 09–10.11: биллинг проекта был отключён примерно с 18:30Z 09.11 до 06:30Z 10.11;
- read-only сверка 10.11.

## 0. Что даёт перенос и чего он не даёт

**Не защищает от отключения биллинга.** 10.11 Cloud Run-задачи упали так же, как Apps Script: образ не загружался,
`ContainerPermissionDenied`. Защита от этого — оплата, бюджетные оповещения и снижение расхода BigQuery
(`docs/ops/BQ_COST_AUDIT_2026-11-10.md`).

**Что даёт:**
1. **Один рантайм вместо двух.**
   - Сейчас загрузка рекламы раз в сутки (02:07Z) после сбоя не повторяется сама; 10.11 её пришлось догонять вручную.
   - Почасовые продажи 10.11 в 10:22 МСК вообще не запустились.
   - В Cloud Run повтор, догонка и проверка «за D−1 есть COMPLETE» делаются одинаково для всех потоков.
2. **Наблюдаемость.** У Apps Script выполнение «завершено» даже тогда, когда запись в BigQuery упала. У Cloud Run
   исход фиксируется кодом выхода и `LOADER_RUNS`, на него можно ставить алерты.
3. **Нет привязки к личной учётной записи.** Триггеры Apps Script принадлежат владельцу; часть из них (заказы,
   поставки) поставлена вручную и в Git не описана. Токены WB лежат в Script Properties без версий.
4. **Подтверждено данными.** 04.11 Apps Script потерял суточный снимок остатков, а shadow-контур Cloud Run его снял.

## 4. Стоимость

- **Каждый запуск платит минимум 10 МБ за таблицу.** Перенос не должен увеличивать число запусков и таблиц на запуск
  относительно Apps Script; расписания берутся из PR #414.
- **Shadow-паритет временно удваивает запись** по переносимому потоку, поэтому окна паритета держим короткими
  (5 дней) и не параллелим больше двух потоков.
- **Базовая линия до начала:** `JOBS_BY_PROJECT` под учёткой Apps Script за 7 дней, с фильтром `statement_type <> 'SCRIPT'`.
