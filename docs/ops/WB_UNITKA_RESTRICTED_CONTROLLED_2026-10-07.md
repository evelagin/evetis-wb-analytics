# WB Юнитка — постоянная политика сверки «урезанный B» (Phase 1B, 2026-10-07)

Статус: реализовано локально в ветке `feat/wb-unitka-restricted-controlled`. **НЕ включено.** Включение —
отдельный OWNER ACK (смена постоянного режима задания `unitka-engine-prod` с `observe`).

## Решение владельца (07.10.2026)

Без владельца прошлые закрытые месяцы окна сверки (35 дней) могут получать ТОЛЬКО:

- A. рост S «Отменили товаров» — поздние отмены Orders API и доказанные отказы вне Orders API (Phase 1A);
- B. первые заполнения автоматических факт-ячеек (в листе пусто, источник дал значение).

Остаются за владельцем: правки и откаты цены, уменьшение S, отзыв источника, прочие поправки.

## Реализация

`UNITKA_CONTROLLED_SCOPE` (новое, по умолчанию `restricted`, опечатка = `restricted`):

| Ячейка прошлого месяца | restricted | full (разовый прогон владельца) |
|---|---|---|
| первое заполнение | пишется | пишется |
| рост S, целое, ≤ Q источника того же дня | пишется | пишется |
| рост S > Q или Q неизвестен | `RECON_CANCELS_EXCEED_ORDERS` | пишется |
| уменьшение S | `RECON_CANCELS_DECREASE_REQUIRES_ACK` | пишется |
| цена, остаток, хранение, заказы, прочее | `RECON_RESTRICTED_REQUIRES_ACK` | пишется |
| отзыв источника | `RECON_WITHDRAWAL_REQUIRES_ACK` | `RECON_WITHDRAWAL_REQUIRES_ACK` |
| месяц LCD / вне окна | `RECON_OUT_OF_SCOPE` | `RECON_OUT_OF_SCOPE` |

Сохраняются все прежние предохранители controlled: только прошлые месяцы окна, потолок ≤ 50 и ≤ 2 % контракта
(на рост S), журнал ремонта обязателен (без него запись не начинается), перечитывание RECON_CONTROLLED_READBACK /
RECON_CONTROLLED_SUMMARY до коммита LCD, заметки S — REFUSAL_NOTES_READBACK.

Стабильность источника: для роста S отдельное правило не нужно — S монотонен (0 откатов за 48 прогонов), доказанный
отказ требует обоих плеч в ОКОНЧАТЕЛЬНОМ недельном слое. Там, где стабильности нет (цена), автозапись запрещена.

## Предлагаемое включение (после ACK)

Одно изменение окружения задания `unitka-engine-prod`: `UNITKA_RECONCILE_MODE=controlled` и `UNITKA_CONTROLLED_SCOPE=restricted`
(охват задаётся ЯВНО, на значение по умолчанию production не опирается — решение владельца 07.10). Расписание прежнее
(07:00 и 09:30 UTC). Откат — `UNITKA_RECONCILE_MODE=observe`. Разовые широкие ремонты — прежним способом:
`gcloud run jobs execute unitka-engine-prod … --update-env-vars UNITKA_RECONCILE_MODE=controlled,UNITKA_CONTROLLED_SCOPE=full`.
Отказы политики пишутся `unitka_controlled_refused` (ERROR с кодом) и остаются в остатке (RECON_RESIDUAL_PERSISTENT) —
сигнал владельцу, как сейчас в observe.
