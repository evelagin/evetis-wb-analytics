# WB Юнитка — доказанные отказы вне Orders API (Phase 1A, 2026-10-07)

Статус: реализовано в ветке `feat/wb-unitka-proven-refusals`, **не развёрнуто**. Развёртывание — по OWNER ACK.

## 1. Проблема

Q листа (`Заказали товаров`) с 04.09.2026 берётся из воронки WB, S (`Отменили товаров`) — только из Orders API
(отмены следующих дней). Воронка содержит заказы, которых Orders API не отдаёт вовсе. Если такой заказ стал отказом,
его отмена в S не попадает, и Юнитка считает его продажей: `W = Q·AI − S·(AI + AF + REVERSE_LEG_RATE) − …`.

## 2. Доказательство правила (production, read-only, 07.10.2026)

| Факт | Значение |
|---|---|
| srid финотчёта с ≥ 2 ненулевыми плечами «Логистика»/«Доставка», без «Продажа»/«Возврат», среди заказов Orders API (май–сент.) | 256 из 256 — `is_cancel = true` |
| Единственный srid «2 плеча + продажа» | возврат после выкупа (eAL.r0beccb…, есть строка «Возврат») |
| Срок продажи после заказа | max 33 дня, p99 18 |
| Срок второго плеча отказа | max 46 дней, p99 30 → **срок зрелости 46 дней** |
| `order_dt` финотчёта | UTC (`…Z`); Orders API и воронка — сутки МСК; 200 заказов с мая — на день раньше |
| Доказанные отказы вне Orders API (по месяцу заказа, МСК) | апр 12, май 19, июн 8, июл 12, авг 13, сен 5 (+1 ждёт окончательного слоя) |
| Независимая проверка R1 | 0 из 2 536 доказанных отказов не являются продажей в Statistics API |

## 3. Правило

`wb_mart.V_UNITKA_REFUSAL_EVIDENCE` (srid) → `wb_mart.V_UNITKA_REFUSAL_DAILY` (сутки × SKU, с 04.09.2026):

- `PROVEN_REFUSAL` — srid нет в `FACT_ORDERS`, нет «Продажа»/«Возврат», ≥ 2 ненулевых плеча, ОБА в окончательном
  (недельном) слое. С провизорным плечом — `REFUSAL_PENDING_FINAL` (ещё не отказ).
- В S: `refusal_counted_qty = LEAST(доказанные, избыток воронки над Orders API)` — только на днях воронки API.
- Избыток без доказательства: `STILL_OPEN` (моложе 46 дней) / `MATURE_BUT_UNPROVEN` (старше) — НЕ входит ни в S,
  ни в «доказанные продажи». Guard построчно показывает STILL_OPEN (EXPECTED_DELAY, строка предварительная); без
  доказательства и с неподтверждённой суммой воронки старше 14 дней — прежний ERROR правила 9 (эскалация сохранена).
  Окно Guard ≤ 35 дней, поэтому зрелые (> 46 дней) единицы считает QA магазина: `qa_refusals_v1.sql` R5 по всей эпохе.
- `cancels_source = 'PROXY_FACT_ORDERS+FINANCE_REFUSAL'`; ячейка S получает заметку `ОТКАЗ ВНЕ ORDERS API` (srid,
  логистика финотчёта). Движок снимает только свои заметки.

### Ограничение окна сверки (важно для сроков)

Прошлый месяц пишется только сверкой, а она видит 35 дней `[LCD−34, LCD]`. Отказ, доказанный позже (второе плечо
до 46 дней + недельная финализация), когда его день уже вышел из окна, автоматически в лист НЕ попадёт — это закрывает
ограниченный исторический манифест (Phase 9). Сроки для сентября 2026: 05.09 (DK741) уходит из окна, когда LCD > 09.10
(прогон 10.10 ещё видит его), 08.09 — LCD > 12.10, 10.09 — LCD > 14.10. 29.09 (FG765) должен стать окончательным до
LCD > 02.11.

## 6. Откат

Обратный порядок: (1) прежний образ, (2) `tools/unitka_refusals_deploy.py … --rollback --apply` — 4 вью получают тела
до изменения (`sql/unitka/refusals_v1_rollback/`). Две новые вью остаются (их никто не читает); DROP — отдельное
решение. Новый образ на старых вью не работает (нет колонок) — поэтому образ откатывается первым.
После отката старый образ вернёт S без отказов, но заметки `ОТКАЗ ВНЕ ORDERS API` останутся — их нужно снять отдельной
ограниченной записью (repeatCell note='' только для ячеек с этой меткой; список — по перечитыванию листа).
