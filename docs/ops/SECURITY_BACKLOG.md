## F-18 · Сервис коммуникаций открыт в интернет — HIGH · OPEN

**Обнаружено:** 2026-09-08, Stage A / A2.
**Назначено:** отдельный этап security hardening.
**Блокирует:** любую новую write-capable автоматизацию и репрайсинг (см. §«Гейт» ниже).

### Факт

`evetis-wb-communications` (europe-west1) — единственный канал записи из системы
EVETIS во внешний маркетплейс: публикует ответы на отзывы и вопросы покупателей
в Wildberries.

| Свойство | Значение |
|---|---|
| `ingress` | `INGRESS_TRAFFIC_ALL` |
| IAM сервиса | `roles/run.invoker` выдан `allUsers` |
| Аутентификация `/poll` | статический заголовок `X-Scheduler-Secret` |
| Где лежит значение заголовка | в открытом виде в конфигурации Cloud Scheduler `evetis-wb-poll` и в Secret Manager (`EVETIS_SCHEDULER_SECRET`) |
| Что доступно за этим эндпоинтом | публикация в WB, ключ OpenAI, бот Telegram, запись в `evetis_communications` |

То есть эндпоинт вызывается кем угодно из интернета, а единственный секрет
читается любым, у кого есть доступ на чтение Cloud Scheduler в проекте.

### Почему не исправлено на Stage A

Перевод на IAM-аутентификацию (`ingress=internal-and-cloud-load-balancing`,
снятие `allUsers`, OIDC-токен у планировщика) меняет способ вызова сервиса.
Ошибка в порядке действий останавливает публикацию ответов покупателям. Это
самостоятельное изменение поведения production, а Stage A по своему контракту
поведения не менял.

### Предлагаемый порядок устранения

1. Выдать `sa-scheduler-prod` (или отдельному SA) `roles/run.invoker` **поресурсно**
   на `evetis-wb-communications`.
2. Перевести `evetis-wb-poll` на `oidcToken` с `audience` = URL сервиса.
3. Проверить успешный вызов, **не снимая** `allUsers`.
4. Только после успешного вызова снять `roles/run.invoker` у `allUsers`.
5. Перевести `ingress` в `internal-and-cloud-load-balancing`.
6. Убрать `X-Scheduler-Secret` из заголовков планировщика; проверку заголовка в
   коде оставить до конца перехода как второй рубеж, затем удалить.
7. Ротировать `EVETIS_SCHEDULER_SECRET` — значение считалось из конфигурации
   планировщика и должно считаться скомпрометированным.

Откат на каждом шаге: вернуть предыдущее значение одного изменённого поля.
Аварийная остановка публикации на время работ:

```bash
gcloud run services update evetis-wb-communications \
  --project=project-fa311fc0-4d87-4781-986 --region=europe-west1 \
  --update-env-vars WB_PUBLISH_ENABLED=false,WB_QUESTION_PUBLISH_ENABLED=false
```

### Гейт

🔴 **Пока F-18 открыта, в системе не должно появляться новых компонентов с
правом записи во внешние сервисы** — в том числе репрайсера (Stage I) и любой
автоматизации ставок, которая пишет в кабинет. Наблюдатель цен остаётся
read-only, и это свойство обязано сохраняться.

Основание: сейчас периметр записи в маркетплейс — один сервис с публичным
эндпоинтом. Добавлять к нему второй write-путь, не закрыв первый, значит
умножать площадь атаки вместо её сокращения.
