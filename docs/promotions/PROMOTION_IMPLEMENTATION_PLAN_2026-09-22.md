## Инфраструктурная оговорка, действующая на весь план

Согласно `CLAUDE.md` и `docs/ops/STAGE_0_CLOSURE_2026-09-11.md` §5, обычный
`terraform apply` из `main` запрещён, пока работа по загрузчику воронки не слита в `main`
через PR: полный план предложит удалить ресурсы воронки, а деплой из `main` откатит образ.

Поэтому **все** инфраструктурные шаги этого плана (PR-PROMO-0 и PR-PROMO-1) выполняются
только **целевым apply с просмотренным планом**, через `.github/workflows/infra.yml`
(`workflow_dispatch`, ручной approval в environment `infra`), и ожидаемый план обязан
быть вида «N to add, 0 to change, 0 to destroy». Любое `change`/`destroy` в плане
останавливает развёртывание.

## Последовательность во времени

```
неделя 0   PR-PROMO-0  →  PR-PROMO-1 (scheduler paused → ручной прогон → снятие паузы)
неделя 0–1 PR-PROMO-2  →  PR-PROMO-3     ← здесь движок уже отвечает на вопросы 1–7, 9–12 по Ozon
неделя 1–4 накопление снимков; акции WB и Ozon завершаются, окна закрываются
неделя 4–5 PR-PROMO-4  →  PR-PROMO-5     ← здесь закрывается вопрос 8 (правдоподобие роста)
неделя 5–6 PR-PROMO-6  →  PR-PROMO-7
```

Полезность появляется на неделе 0–1, а не в конце: уже после PR-PROMO-3 владелец видит,
какие SKU участвуют в акциях Ozon, по какой цене, что это даёт вкладу и какой рост продаж
потребовался бы, — то, что сегодня проверяется руками в кабинете и не проверяется вовсе
по WB.
