# PR-PROMO-3 — экономика акций на каноне Forward economics

**Дата:** 2026-09-24. **Статус:** реализовано (часть I, PR #168), развёрнуто из `main e6006b6`,
расписание снимков применено Terraform, проверено на живых объектах и на новом слоте, снимок
production внесён в манифесты (часть II, §27–§31). **DONE.**

**Вопрос слоя:** что будет с юнит-экономикой EVETIS, если этот SKU продаётся по этой цене акции.
**Не вопрос слоя:** входить ли в акцию. Рекомендаций, запасов, исторического роста продаж,
политики 20 % здесь нет — это PR-PROMO-4+.

**Решение владельца 2026-09-24:** канон экономики акций — Forward economics (WB `WB_FE_V1`,
Ozon `FORWARD_MODELLED`). Действующая Юнитка WB и Ozon не меняется и к Forward economics не
приводится; расхождение с Юниткой — известное различие контрактов, оно замерено (§18),
а не устранено.

## 2. Текущий контракт WB (`WB_FE_V1`, production = Git)

`contribution_before_ads_pre_tax(P) = P − P·take − L − C`, `take = (комиссия% + эквайринг%) / 100`.

| Компонент | Источник | Как в формуле |
|---|---|---|
| Цена продавца (база) | `V_WB_PRICES_CURRENT.seller_effective_price` (цена после скидки продавца, до СПП) | P |
| Комиссия | тариф `paidStorageKgvp` по предмету + `REF_MARKETPLACE_COMMISSION_COMPONENT` | доля цены |
| Эквайринг | эмпирика 45 сут: EXPECTED p50, стресс p90 | доля цены |
| Логистика | Σлогистики / Σпродаж за 90 сут — **нагрузка на проданную единицу, невыкуп внутри** | постоянная сумма |
| Возвраты / невыкупы | внутри логистики (1,2–1,7 логистических события на продажу) | — |
| COGS | `evetis_ref.V_PRODUCT_COGS_EFFECTIVE` на дату | постоянная сумма |
| Break-even | `(L + C) / (1 − take)` | корень той же функции |
| Хранение, налог, реклама, приёмка, штрафы | исключены (`PRE_TAX`) | — |

Канон считает в `FLOAT64` (эквайринг — `FLOAT64`); слой акций повторяет ту же арифметику.

## 3. Текущий контракт Ozon (`FORWARD_MODELLED`, production = Git)

`contribution_case(P) = P − COGS − комиссия(P) − эквайринг(P) − логистика_case − last_mile`.

| Компонент | Источник | Как в формуле |
|---|---|---|
| Цена продавца (база) | `RAW_OZON_PRICES.marketing_seller_price` последнего суточного снимка | P |
| Комиссия FBO | `sales_percent_fbo`, база `SELLER_BASE_PRICE` | доля цены |
| Эквайринг | сумма API; канон в break-even — `ROUND(эквайринг/P·100, 4)/100`; факт: **1,0000 % у 20 из 20** | доля цены |
| Логистика EXPECTED | медиана наблюдений с 28.08, иначе min × 1,20, в границах тарифа | постоянная |
| Логистика WORST | `fbo_direct_flow_trans_max` (тариф) | постоянная |
| Last mile | `fbo_deliv_to_customer` | постоянная |
| Возвраты | **не входят** (`CANCEL_ONLY_RETURNS_EXCLUDED`); отмены — отдельная мера `expected_contribution_per_created_order_*` | — |
| COGS | `V_PRODUCT_COGS_EFFECTIVE` на `CURRENT_DATE` | постоянная |
| Break-even | `(COGS + last_mile + логистика_case) / (1 − c − a)` | корень |
| Хранение, Premium, налог | исключены | — |

**Асимметрия площадок сохранена:** у WB невыкуп заложен в логистику проданной единицы, у Ozon
возвраты вне вклада. Слой акций это не выравнивает.

## 4. Архитектура: переиспользование канона

**Алгебра канона подтверждена на production** (живые данные, базовая цена): у WB
`P·(1−take) − (L+C)` расходится с `contribution_before_ads_pre_tax_rub` не больше чем на
0,00448 ₽; у Ozon `P·(1−c−a) − (C+L_m+L_e)` — не больше 0,005 ₽. Это копеечное округление самого
канона. Break-even канона — корень той же функции (≤ 0,00485 ₽).

**Отсутствующий примитив** — вычисление канона при цене, заданной построчно. Наименьшее
изменение, без правки канона и Юнитки:

```
канон FE (вью «сейчас»)
      │  CALL на каждом слоте, КОПИЯ без арифметики
      ▼
*_PROMO_ECONOMICS_BASIS_SNAPSHOT (append-only)   ← неизменная история канона
      │  раскладка: удерживаемая доля r и постоянные издержки F
      ▼
V_*_PROMO_ECONOMICS_BASIS_HISTORY
      │  вклад(P) = P · r − F   — одно выражение, то же, что в break-even канона
      ▼
V_*_PROMO_ECONOMICS_SCENARIO_HISTORY → evetis_mart (объединение, текущее, покрытие)
```

Второго движка нет: в слое акций не вычисляется ни один компонент стоимости — комиссия,
эквайринг, логистика, COGS, break-even приходят из снимка канона. Проверки: офлайн-тест
`test_no_second_economics_engine` (вью не читают ни одного источника экономики),
`test_procedures_copy_canonical_views_without_arithmetic` (процедура копирует голые колонки
канона), `test_single_algebra_of_the_canon` (выражение вклада одно на сценарий), E08 на
production (базовая цена = канон).

**Применимость цены — отдельная ось, а не условие расчёта** (`price_binding_evidence`).
Экономика условна: «если продано по P». Применение к продажам доказывается сравнением с
`marketing_seller_price` того же наблюдения:

| Значение | Правило | Факт (текущий слот) |
|---|---|---|
| `APPLIED_TO_DEFAULT_SELLER_PRICE` | цена акции = `marketing_seller_price` < прейскуранта | 6 |
| `EQUAL_TO_CURRENT_SELLER_PRICE` | = текущей цене продавца (участие бесплатно) | 22 |
| `ABOVE_CURRENT_SELLER_PRICE_NOT_APPLIED` | выше текущей; цена по умолчанию не изменилась (448 / 448 строк за 7 слотов) | 65 |
| `BELOW_CURRENT_SELLER_PRICE_NOT_REFLECTED_IN_DEFAULT_PRICE` | ниже, но цена по умолчанию не сдвинулась — региональная акция (593111986 «Сибирь» 1229 при 1320: 7 / 7) | 1 |
| `HYPOTHETICAL_ENTRY` / `SCHEDULED_FUTURE_ENTRY` / `ELIGIBLE_FUTURE_ENTRY` | кандидат / запланировано / возможно | 61 / 18 / 47 |

Региональный охват «Акций для складов» из полей API не доказуем (`with_targeting = FALSE` у
всех) — поэтому это ось доказательности, а не фильтр.

### 5.2 Никогда не смешивается

Цена покупателя, СПП, `old_price`, отображаемая цена, `max_action_price` участника,
`action_price` кандидата в вклад не подставляются. СПП финансирует WB и выплату продавца не
уменьшает (тождество `for_pay = P·(1−комиссия) − эквайринг` доказано на 38 698 строках, шапка
`pr2_wb_forward_economics.sql`) — в экономике продавца её нет; отдельный контекст цены покупателя
не выводится, потому что до заказа она не наблюдаема.

### 5.3 WB

Автоакции: состав по SKU не наблюдаем (PR-PROMO-2) — **строк экономики акция × SKU нет**.
Лестница бустинга несёт долю участия и бустинг, **цены не несёт** — законного порога цены для
известного SKU в ней нет. `/nomenclatures.planPrice` (обычные акции) — смысл не доказан живыми
данными (таких акций у EVETIS не было) → `PRICE_SEMANTICS_UNPROVEN`, экономика не считается.

## 6. Базовая цена (BASELINE)

BASELINE = канонический сценарий при текущей цене продавца **из снимка того же слота**:

| | WB | Ozon |
|---|---|---|
| Цена | `seller_effective_price_rub` | `seller_base_price` |
| Момент цены | `price_observed_at` (наблюдатель цен, каждые 20 мин) | `tariff_snapshot_at` (суточный снимок цен) |
| Экономика | `WB_FE_V1`, снимок слота | `FORWARD_MODELLED`, снимок слота |

BASELINE **не экономика акции** (`promotion_link_evidence = NO_PROMOTION_LINK`,
`source_promotion_id = NULL`) — это текущая экономика продавца, на которой доказывается
совпадение с каноном. Если канон Ozon уже учитывает действующую акцию (цена продавца ниже
прейскуранта), строка несёт `baseline_includes_promotion_effect = TRUE`: дельта к такой базе
занижает цену участия.

Цена продавца, которую видел наблюдатель акций в том же слоте, — `observed_seller_price_rub`,
для сверки; базу она не заменяет.

## 8. COGS

Единственный источник — канон (`V_PRODUCT_COGS_EFFECTIVE` через FE), на дату снимка, с
`cogs_effective_from`. Своей таблицы COGS нет. Наборы — как в каноне: у набора свой COGS в
справочнике (он есть у 22 из 25 WB-SKU и 20 из 20 Ozon); если его нет, канон `BLOCKED`, сценарий
`MISSING_COGS`. BOM-политики в слое нет.

## 9. EXPECTED

`baseline_contribution_expected_rub`, `promo_contribution_expected_rub`,
`delta_contribution_expected_rub = promo − baseline`,
`*_margin_expected_pct = вклад / цена сценария × 100` (как `margin_expected_pct` канона, без
округления).

## 10. Downside — у каждой площадки свой

| | WB | Ozon |
|---|---|---|
| Кейс | `WB_STRESS_P90_ACQUIRING_AND_LOGISTICS` | `OZON_WORST_MAX_LOGISTICS` |
| Формула | `P·(1 − (комиссия + эквайринг p90)/100) − (логистика p90 + COGS)` | `P·(1−c−a) − (COGS + last_mile + логистика max)` |
| Класс | `DERIVED_DETERMINISTIC`: канон WB формального стресс-вклада не выводит, но выводит его корень `break_even_before_ads_pre_tax_stress` из тех же слагаемых (E09) | `DIRECT_CANONICAL_CASE`: при базовой цене = `contribution_worst_case` (E09) |

Статистический стресс WB не назван WORST Ozon. `promo_downside_negative` — факт «downside < 0»,
без порогов и без решения.

## 11. Требуемый рост продаж

`required_sales_uplift_pct = (baseline / promo − 1) × 100` — во сколько больше проданных единиц
нужно, чтобы сохранить совокупный вклад. Объём продаж сокращается.

| Случай | Результат | `uplift_status` / `uplift_interpretation` |
|---|---|---|
| оба > 0, promo < base | > 0 | `COMPUTED` / `MORE_UNITS_REQUIRED` |
| promo = base | 0 | `COMPUTED` / `NO_CHANGE` |
| promo > base | **< 0**, не обнуляется | `COMPUTED` / `PROMO_UNIT_CONTRIBUTION_HIGHER` |
| promo ≤ 0 | NULL | `NOT_ACHIEVABLE_PROMO_NON_POSITIVE` |
| base ≤ 0 | NULL | `NOT_MEANINGFUL_BASELINE_NON_POSITIVE` |
| экономика недоступна | NULL | `NOT_COMPUTED_ECONOMICS_UNAVAILABLE` |

Это break-even-арифметика, а не ожидаемый рост; исторического роста в слое нет.

## 12. Граничные случаи и цены-границы

- **Малый положительный вклад:** порога «< 1 % цены» нет — политикой он не утверждён. Сырая доля
  — `promo_margin_expected_pct`.
- **Break-even:** `break_even_price_expected_rub` — **минимальная** цена продавца без
  отрицательного вклада (канонический break-even из снимка), `promo_price_minus_break_even_rub` —
  запас цены акции над ним. «Максимальной допустимой цены» нет — так было бы финансово неверно.
- **Политика 20 %:** источника нет → маржи показаны, ничего не блокируется (PR-PROMO-5).

состояние PR-PROMO-2 одно. WB-часть — вне `sql/current` (граница CANONICAL_COVERAGE §3), как в
PR-PROMO-2.

## 16. История и текущее

История — строка на слот. Текущее выводится только из истории: последний слот сценария;
`present_in_latest_slot = FALSE`, если сценарий исчез (товар стал участником, акция закрылась),
его экономика — на `last_economics_slot`. Свежесть — `basis_age_minutes`; порога устаревания в
платформе нет, придумывать нельзя.

## 17. Неизменность истории — жёсткий гейт

Вью поверх канона «сейчас» переписали бы прошлое при новом COGS, тарифе или окне логистики —
это доказано устройством канона (§1). Решение:

- **снимок**: процедура на каждом слоте копирует строки FE-вью в append-only таблицу;
  идемпотентна по слоту (`WHERE NOT EXISTS`), не обновляет и не удаляет; откат таблицы не
  трогает (`pr_promo3_rollback.sql`);
- **экономика только из снимка своего слота**; нет снимка — `TEMPORAL_ALIGNMENT_UNAVAILABLE`;
- **расписание**: Cloud Scheduler → BigQuery `CALL`, :10 после каждого слота, отдельный SA на
  площадку, запись — потабличная (`infra/terraform/promo_economics_snapshot.tf`); пропуск слота
  виден проверкой E15.

Доказательство на фикстурах: COGS и комиссия второго слота изменены (FE21, FE22) — экономика
первого слота прежняя (FE23: COGS 460,5; вклад 290; снимок `…202601010400`).

Цена неизменности: у 6 слотов, наблюдённых **до** первого снимка (22.09 14:00 – 23.09 19:00), снимков
нет, и их экономика — `TEMPORAL_ALIGNMENT_UNAVAILABLE` (1 356 строк). Задним числом снимок не создаётся: это был бы
подлог времени знания.
