## «2025 под сентябрь» — приведение истории к модели сентября

Что меняется в цифрах истории (владелец должен принять пересчёт): отмены по модели B (потери
вырастут), хранение — факт вместо `T×k` там, где есть источник (финотчёт `storage_fee` — глубже
01.09; `RAW_WB_PAID_STORAGE` — только с 01.09), остатки — факт из `FACT_STOCKS_SNAPSHOT` (история
снимков в BigQuery короче 2025 года; где факта нет — остаётся проекция с пометкой), COGS — по
партиям из `REF_SKU_COGS_HISTORY` (источник правды по решению 31.08), ДРР месяца — взвешенный.
Механика: не ручные правки, а тот же Engine в режиме `BACKFILL` по секции (месяц как параметр),
план-диф → QA → запись; Engine v1.2 должен уметь адресовать секцию по строке шапки, а не
константой `GRID.TOP = 735`.

## Новые SKU — автоматический блок

Сигнал: в `REF_SKU_MASTER` (active, WB) есть nmID, которого нет в строке шапки текущей секции.
Сегодня такой один — **909951444** (в реестре active, в Master отсутствует; по правилу «только
ISSUE»). Engine v1.2: гейт `NEW_SKU_DETECTED` (алерт + журнал) и, **по отдельному решению
владельца**, `s9addblock`-шаг: копия эталонного блока (формулы относительные, УФ, ширины,
COGS из справочника, заголовок `nmID Название`), расширение сводных FILTER-диапазонов не
требуется (они по `MOD(COLUMN,24)` до последнего блока — проверить границу `UT`), обновление
`GRID.NB`. То же для Ozon — после Ozon-Engine.

## Авто-октябрь — новая месячная секция за 1–3 дня до конца месяца

Engine v1.1 (E1.1) — `MONTH_ROLLOVER`: за N дней до конца месяца (параметр, по умолчанию 2)
создать секцию следующего месяца под текущей: шапка/заголовки/дни (28–31)/итог/план, формулы
блока относительные + обёртка `LAST_CLOSED_DATE`, первый день остатка = последний факт прошлого
месяца, сводка/итоги, УФ по контракту E6.1, заморозка/группировка старого месяца. Гейты:
`STRUCTURE_DRIFT` до и после, `FORMULA_ERRORS 0`, `FUTURE_LEAKAGE 0`, повтор — `NO_CHANGE`.
Первый прогон — 28–29.09 в SHADOW (план-диф), затем controlled write; октябрь 2026 —
приёмочный кейс.
