**Проверка после смены:**

## 5. SPP SEMANTICS — доказано, что это НЕ СПП дня заказа

Вопрос был: A) дата заказа, B) дата продажи/выкупа, C) дата финотчёта, D) реконструкция.

**Ответ: B/C.** Доказательство — разброс `spp_percent` внутри ОДНОГО дня заказа по разным датам выкупа:

| Дата заказа | Дата выкупа | СПП |
|---|---|---|
| 01.09 | 02.09 | 32,26 % |
| 01.09 | 03.09 | 30,06 % |
| 01.09 | 06.09 | 0,00 – 32,26 % |
| 01.09 | 07.09 | 3,01 % |
| 01.09 | 08.09 | 0,00 % |

Один и тот же день заказа даёт СПП от 0 % до 32,26 % — значит показатель привязан к выкупу, а не к заказу. Больше того, он различается **между единицами внутри одного дня выкупа**: СПП персональный, это скидка конкретного покупателя.

**Вывести СПП дня заказа математически нельзя:** `retail_price` = `retail_price_withdisc_rub` = цена продавца (499 ₽), `sale_percent` = 0, поля цены покупателя в источниках нет.

Поэтому:

* **operational SPP → PENDING/MANUAL.** Значения, записанные в R2, сняты из книги — они были реализованными и в контуре заказов вводили в заблуждение;
* **realized SPP сохранён** в `V_WB_FINANCE_CANONICAL` для второго контура;
* контуры не смешиваются.

Важно для экономики: **на выручку продавца СПП не влияет.** `for_pay` считается от цены продавца, WB компенсирует свою скидку сам. Пустой СПП модель не ломает.

## 6. COMMISSION — валидация на 212 наблюдениях

Модель: `for_pay = цена продавца × (1 − TOTAL_COMMISSION_RATE)`.

| Компонент | Значение | Характер |
|---|---|---|
| базовая комиссия | **42,25 %** | константа во всех строках; тариф WB `kgvpBooking` («Кремы», FBW) = 42,5 % |
| эквайринг | **3,07 %** | **переменный: 1,66 – 4,88 % по строкам** — зависит от способа оплаты покупателя |
| **TOTAL_COMMISSION_RATE** | **45,32 %** | база: цена продавца до СПП |

Implied по 51 выкупу сентября: `1 − SUM(for_pay)/SUM(price)` = **45,3155 %** — сходится с суммой компонентов.

**Ошибка модели на 212 выкупах (11.08–09.09):**

| Метрика | Значение |
|---|---|
| MAE | **2,24 ₽ (0,9 %)** |
| MAX abs | **8,5 ₽ (3,4 %)** |
| эффективная ставка по строкам | 43,91 % … 47,13 % |

Расхождение материальным не является и **полностью объясняется разбросом эквайринга** — дополнительных компонентов удержания не найдено. Способ оплаты покупателя заранее не известен, поэтому меньшей ошибки на уровне единицы не бывает в принципе.

История ставок — `evetis_ref.REF_WB_COMMISSION_HISTORY`, с полем `rate_base = PRICE_WITH_DISC`: комиссия WB начисляется на цену покупателя, а юнитка считает от цены продавца, и без явной базы ставка бессмысленна.

## 9. MONTH TOTALS — корректные агрегации

Ссылок на строку заголовков не осталось ни в одном из 24 блоков (проверено регулярным выражением по всей строке 767).

| Показатель | Формула итога |
|---|---|
| заказы, отмены, показы, реклама, доходность, хранение, самовыкупы, внешняя реклама | `SUMIF(даты; "<="&LAST_CLOSED_DATE; …)` |
| логистика | `SUMPRODUCT((даты<=LAST_CLOSED_DATE) × ставка_дня × заказы_дня)` |
| остаток | `INDEX(...; MATCH(LAST_CLOSED_DATE; даты))` — остаток на последний закрытый день |
| оборачиваемость | остаток на LAST_CLOSED / (SUM(заказы) / число закрытых дней) |
| доходность на 1 шт | `SUM(доходность) / SUM(заказов)` |
| **ДРР** | `SUM(реклама) / SUM((заказы − самовыкупы) × цена с СПП)` |

**Доли больше нигде не суммируются и не усредняются как проценты** — ни ДРР, ни доходность на единицу, ни оборачиваемость.
