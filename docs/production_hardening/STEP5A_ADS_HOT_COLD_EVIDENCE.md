# ADS fullstats HOT/COLD — evidence и контракт (фильтр НЕ включён по умолчанию)

## Факты (BQ, 15.09)
1. 431 id в fullstats: status 7 = 373, 11 = 49, 9 = 9. 9 батчей по 50 × пауза 21 с ≈ 168 с сна.
2. Прогон 15.09 17:00: 373 завершённые → 372 заглушки no-stats, **0 ненулевых строк**.
3. Значения fullstats после первой загрузки не менялись: 1 756 ключей, наблюдавшихся ≥ 6 дней, 0 изменений.
4. ❌ Критерий «недавно ненулевая» небезопасен: возобновления после тишины 8–14 дн (49), 15–30 (34), 31–60 (6), >60 (2, max 73).
5. ❌ status 7 не терминален для статистики: 80 кампание-дней ПОСЛЕ первого наблюдения статуса 7 (до ~40 дней, 5–100 показов, 1–75 ₽).
6. ❌ `end_time/change_time` ненадёжны: 125 завершённых имели ненулевые дни после change_time.
7. Цена хвоста завершённых: 07.2026 49,9 ₽ (0,066 %), 08.2026 3,0 ₽ (0,007 %), 09.2026 0 ₽.

## Вывод
Контракт «ноль потерь на момент закрытия дня» с фильтром доказать НЕЛЬЗЯ.
Доказуем контракт «конечная полнота с ограниченной задержкой»:

- HOT (ежедневно, окно D−7…D−1): status ∈ {9, 11} ИЛИ status 7 с первым наблюдением статуса 7 за последние 60 дней
  ИЛИ с ненулевой статистикой за последние 60 дней. Сбой чтения признаков → все id HOT (fail-safe).
- COLD (ротация): остальные id делятся на 8 шардов `MOD(advertId, 8)`; ежедневно опрашивается шард
  `MOD(day_of_year, 8)` окном D−14…D−1 (1 батч, +21 с).
- Полнота: каждый COLD id опрашивается раз в 8 дней окном 14 дней > 8 → ни один день не выпадает;
  значения стабильны (факт 3), дедуп V_ADV_CAMPAIGN_STATS newest-wins — повторы безопасны.
- Worst-case задержка обнаружения: 8 суток. Эффект: закрытый день может получить
  LATE_SOURCE_CORRECTION рекламы ≤ 8 дней спустя; исторический максимум ≈ 50 ₽/мес.
- Runtime: ~60–80 HOT id → 2 батча + 1 COLD = 3 вызова, 2 паузы (≈ 45–60 с вместо ≈ 190 с).

## Не проверено (блокирует включение)
- Какой источник даёт `MART_SKU_DAILY.ad_spend`: fullstats `sum` или costs (upd). Если costs — задержка
  COLD влияет только на показы/клики, не на деньги. Проверить по SQL в репо.
- Полный sweep раз в неделю как reconciliation-контроль (сравнить ротацию с полным опросом 2 недели в SHADOW).

## Рекомендация
Не включать в 5A. Реализовать под флагом `WB_ADS_HOT_COLD_MODE = OFF | SHADOW | ON`, 14 дней SHADOW
(логировать разбиение, сверять с полным опросом), затем OWNER GATE. Защиту от kill в 5A даёт
дедлайн-гард + catch-up без фильтра.
