# WB STORE P&L 2.0 — раскладка вкладки «WB Магазин P&L» (UX, 2026-10-16)

OWNER 2026-10-16 «WB STORE P&L 2.0» (feature branch; production и main не меняются — заморозка main ради Heldi #352).
Модель, источник и суммы не меняются: вкладка — представление `wb_mart.V_WB_STORE_PNL_PRESENTATION` (история H0 +
Phase C). По образцу «Ozon Магазин P&L» (`OZON_STORE_PNL_PHASE_D4.md` §10).

## Раскладка (контракт `LAYOUT_VERSION = wb-ux-2026-10-16`, 26 колонок A:Z)

| Строки | Содержимое |
|---|---|
| 1–2 | Заголовок; источник и оговорки (не бухгалтерская прибыль; налог 2 % внутри «Вклада SKU») |
| 3–5 | Ключевые показатели текущего и прошлого года — над своими колонками, = ячейки строк «Итого» |
| 6 | Полоса групп: продажи · вклад · поправки · кабинет WB · доходы WB · чрезвычайные статьи · финансовый результат · достоверность |
| 7 | Заголовки колонок; заметки — контракт |
| 8+ | Месяцы по годам (группа строк) и «Итого <год> · <период>» |

- Колонки «Поправки к факту — всего» и «Расходы кабинета WB — всего» — суммы показанных подробных колонок; подробные
  свёрнуты кнопкой «+». В свёрнутом виде основные колонки (выручка … результат без чрезвычайных статей) видны без
  горизонтальной прокрутки.
- **Чрезвычайные статьи** — отдельный блок: списание утраченного товара, компенсация WB, чистый эффект (справочно).
  Двойного учёта нет: в прибыль входят две первые колонки, чистый эффект — справочно (тождество строки проверяется
  кодом). Новая справочная колонка «Результат без чрезвычайных статей» = прибыль − чистый эффект.
- **Налог 2 %** — расшифровка внутри «Вклада SKU» (свёрнутая подробная колонка), повторно не вычитается.
- Тождество строки: прибыль = вклад SKU + поправки − расходы кабинета + доходы WB − списание + компенсация.
- «Пояснение» — причины неполноты только из полей вью (нефинальный финотчёт, неразобранные операции, неизвестные расходы,
  дни биллинга рекламы, ожидаемые счета WB, дозревание когорты, утрата товара, источник месяца).
- Итоги года: суммы показанных ячеек; маржа = Σ прибыль ÷ Σ выручка.
- **Три результата (OWNER DECISION 16.10).** Август 2026 (`LEGACY_PARTIAL_KNOWN_DEFECTS`) остаётся в общем результате:
  утрата товара — реальное событие, но месяц не окончательный. Показываются: **A** «Управленческая чистая прибыль
  магазина» — полный результат, с чрезвычайными статьями; **B** «Результат без чрезвычайных статей» = A − чистый эффект
  форс-мажора (справочно); **C** «Сопоставимый результат без наследия» = прибыль месяцев без статуса наследия (у августа
  ячейка пуста, не 0; справочно, не полный результат года). Инварианты: A = B + чистый эффект (эффект учтён один раз);
  C = A − Σ прибыли месяцев наследия. Живые данные 2026: A −494 565,19; B +93 020,26; C −75 449,70.
  «Итого» раскрывает месяц наследия и его прибыль в «Пояснении».
- Раскладка идемпотентна (прежние УФ, объединения и группы снимаются в том же batchUpdate); запросы раскладки
  проверяет `assertOwnTab` (название, индекс и видимость вкладки не меняются; сетка только расширяется — колонки до Z,
  строки — когда план не помещается). Каждая запись сбрасывает форматы и заметки всей сетки вкладки в строках плана
  (включая колонки правее Z и ручные заметки ячеек); вне вкладки — ничего. Отпечаток остальных вкладок книги
  сверяется до и после записи (`STORE_PNL_OTHER_TABS_CHANGED`), как у Ozon. Общий `assertOnlyTab`,
  `contentSha`, `normalizeGrid` (их использует Ozon) не изменены. Блок публикации вынесен в `publishStorePnlTab`
  (загрузчик и репетиция исполняют один код).

## Репетиция (тестовая книга, копия боевой вкладки)
Боевая вкладка (A:U, сетка 20×21, заметки строки 1, отпечаток 542dd941…, контракт 77efab2d…) скопирована в тестовую
книгу; живая вью — только чтение:
W1 без допуска — отказ `STORE_PNL_CONTRACT_MIGRATION_REQUIRED` до записи; W2 миграция — WRITE migrated, перечитывание
PASS; W3 после ручного сворачивания группы и подмены контракта — перераскладка без дублей (9 правил УФ, 9 объединений,
3 свёрнутые группы колонок, группа года развёрнута, скрытых строк нет); W4 — NOOP; W5 — смена подписей → WRITE; W6/W7 после ревью — WRITE/NOOP; W8 миграция на 26 колонок (показатель C) — WRITE, W9 — NOOP.

## Перевод боевой вкладки (отдельный OWNER ACK, после снятия заморозки main)
merge → образ из main только на `unitka-store-pnl-prod` (без общего deploy-prod) → один прогон с переопределениями
выполнения `UNITKA_STORE_PNL_PUBLISH=1` и `UNITKA_STORE_PNL_MIGRATE_CONTRACT=<contractSha>` (в новом часе МСК) →
независимое перечитывание и сверка с вью. Плановый прогон без допуска миграцию не выполнит (отказ до записи), поэтому
до перевода Scheduler WB P&L нужно поставить на паузу или выполнить перевод сразу после развёртывания образа.

## Откат
Вкладка: владелец очищает вкладку (значения, форматы, объединения, группы, УФ, закрепление), прежний образ, один прогон
с `UNITKA_STORE_PNL_ADOPT_SHA=<отпечаток пустого содержимого>` и `UNITKA_STORE_PNL_MIGRATE_CONTRACT=<contractSha A:U>`.
