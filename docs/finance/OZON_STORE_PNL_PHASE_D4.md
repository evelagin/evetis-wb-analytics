## 1. Контракт представления

- Книга Юнитки (`UNITKA_SPREADSHEET_ID`), новая вкладка **«Ozon Магазин P&L»**, одна строка на месяц P&L.
- Единственный финансовый источник — `ozon_mart.V_OZON_STORE_PNL_MONTHLY`. Собственных финансовых формул нет: каждая
  денежная колонка — колонка вью; две колонки-группировки (расходы кабинета без Premium = 12+77+46+76+57; прибыль без
  оценки X = Y − X) — суммы колонок той же вью.
- 26 колонок A:Z, заголовок и заметка каждой — системный контракт (`contractSha()`), смена схемы — только управляемой
  миграцией `OZON_STORE_PNL_MIGRATE_CONTRACT` по OWNER ACK.

| | Колонка | Источник (D3) |
|---|---|---|
| A | Месяц | `pnl_month` |
| B | Выручка продавца | `seller_base_revenue_rub` |
| C | Себестоимость | `product_cogs_rub` |
| D | Комиссия Ozon | `commission_rub` |
| E–K | Логистика, последняя миля, обратная логистика, эквайринг, хранение, продвижение SKU, прочие прямые | E…K |

| S | Предварительная оценка X | X (курсив, оранжевым) |

Состояния (не-окончательные месяцы так и подписаны): «Деньги Ozon сверены, себестоимость предварительная» (деньги Ozon
окончательны при закрытом месяце; себестоимость — нет, до D3.1, §8), «Сверены, ждём поздних начислений», «Ждём начислений
Ozon — предварительно», «Не доказан — нужна сверка», «Не хватает денег источника», «Есть неразобранные операции».
«Причина неполноты» — по строке, из ворот D3: известные дефекты, открытые сутки контроля D1, деньги без колонки или
отправления, SKU вне карты, себестоимость не найдена, признаки незагруженного сторно, ремонт D1 без сверки, оценка X и её
входы, единицы в пути, предварительная себестоимость. Денежная колонка NULL — отказ (неизвестное ≠ 0); NULL маржи — пусто.

## 2. Гейты публикации (строже WB)

Модель (`OZON_STORE_PNL_PUBLISH_GATE`, публикация блокируется целиком): **канонический QA D3 Q01–Q23**
(`sql/ozon/qa_ozon_store_pnl_v1.sql`, вшит в образ строкой `qa.ts`, тест требует побайтного равенства с файлом;
перегенерация `node scripts/gen_ozon_store_pnl_qa.mjs`) — любой FAIL, ошибка запроса или незнакомый статус, а также
отсутствие результатов QA; запросы идут параллельно по 6; пустая вью; неизвестное состояние/закрытие;
любой месяц PENDING_CLASSIFICATION; строки `V_OZON_FINANCE_NEW_OPERATIONS`; нарушение тождеств > 0,02 ₽; «Деньги Ozon
сверены» при открытых условиях (месяц не закрыт, X ≠ 0, доставлено без начисления, известный дефект); «ждём поздних»
у закрытого месяца; пропуск месяца; деньги RAW ≠ леджер, деньги без колонки или без отправления
(`V_OZON_STORE_FINANCE_COVERAGE`).

Источники (`OZON_STORE_PNL_SOURCE_NOT_READY`): `source_freshness_state` ≠ FRESH (`V_OZON_MART_FRESHNESS`). Свежесть
включает и загрузки Performance (`ads_expense_daily`, `ads_sku_daily`): их сбой (как 403 12.10) тоже остановит
публикацию, хотя прибыль магазина берёт рекламу из финансовых начислений, — консервативно, вкладка остаётся на прошлой версии.

Известные WARN QA (Q16 мост к L4, Q20 застывшие отправления) гейтом не являются: они раскрыты в состоянии и причине месяца.
Без `OZON_STORE_PNL_PUBLISH=1` Sheets не открывается вовсе; гейты только пишутся в журнал (`ozon_store_pnl_publish_gate`).

## 3. Публикация: отпечаток, NOOP, перечитывание

- План → `fingerprint` (sha256 вкладки, заголовков, заметок, строк) в журнал `ozon_store_pnl_tab_plan`.
- Отпечаток содержимого A:Z — developer metadata `evetis.ozon_store_pnl.published_sha`, контракт —
  `evetis.ozon_store_pnl.contract_sha`.
- Решение: содержимое = план → **NOOP** (ни одного запроса записи); содержимое = последнему опубликованному → WRITE;
  пустая вкладка без отпечатка → первая WRITE; иначе — отказ (`OZON_STORE_PNL_TAB_EDITED` / `TAB_UNTRACKED`),
  восстановление только `OZON_STORE_PNL_ADOPT_SHA` владельца.
- Исторические корректировки D3 отражаются сами: следующий прогон видит другое содержимое вью и перезаписывает строки
  (source-driven UPDATE); ручной фиксации месяцев нет.
- Перед WRITE в журнал — **манифест отката** `ozon_store_pnl_rollback_manifest` (прежнее содержимое, его отпечаток и контракт).
- Значения, форматы, заметки и оба отпечатка — один атомарный `batchUpdate`.
- Перечитывание: значения = план, один отпечаток = план, контракт = код, заметки = контракт, **отпечаток остальных
  вкладок книги** (sheetId, название, индекс, сетка) до и после записи совпадает — иначе `OZON_STORE_PNL_OTHER_TABS_CHANGED`.

## 9. Откат

- **Откат раскладки v2 → v1 (A:AE → A:Z).** Одного возврата образа недостаточно: v1 не знает раскладки v2 (объединения
  полосы и показателей, УФ, группы, закрепление 7 строк) и отказывает `TAB_EDITED` (отпечаток A:Z ≠ опубликованному A:AE)
  — это безопасно. Основной путь (без смены sheetId и без записи вне загрузчика): (1) `PUBLISH=0`; (2) владелец
  очищает вкладку в интерфейсе — значения, форматы, объединения, группы, УФ, закрепление (developer metadata остаются);
  (3) образ v1; (4) прогон v1 откажет `TAB_EDITED` и напечатает отпечаток пустого содержимого; (5) один прогон с
  `PUBLISH=1`, `OZON_STORE_PNL_ADOPT_SHA=<этот отпечаток>` и `OZON_STORE_PNL_MIGRATE_CONTRACT=<contractSha v1>` —
  переменные удаляются сразу после него. Запасной путь — удалить вкладку и создать пустую с тем же названием: новый
  sheetId в `OZON_STORE_PNL_SHEET_ID` и в F-18 (решение владельца), первая публикация без миграции.
  Манифест отката в журнале содержит только ЗНАЧЕНИЯ прежней вкладки, не раскладку.

- Публикация: снять `OZON_STORE_PNL_PUBLISH` (=0) — вкладка остаётся на последней опубликованной версии, запись невозможна.
- Содержимое: манифест отката в журнале (прежние значения и отпечаток) → восстановление владельцем, затем
  `OZON_STORE_PNL_ADOPT_SHA` текущего содержимого на ОДИН прогон и удаление переменной сразу после него (как у WB §11);
  то же для `OZON_STORE_PNL_MIGRATE_CONTRACT`.
- Инфраструктура: Scheduler на паузу (`scheduler-control.yml`); Job и алерт — `terraform destroy -target` по решению владельца.
- Вкладка: удаление — решение владельца; другие вкладки загрузчик не трогает.

OWNER 2026-10-16: вкладка неудобна для управленческого анализа. Модель D3 и числа не меняются, меняется только
представление (контракт `LAYOUT_VERSION = ux-2026-10-16`, 31 колонка A:AE):

| Строки | Содержимое |
|---|---|
| 1–2 | Заголовок; источник, дата финансов Ozon, оговорка «не бухгалтерская прибыль» |
| 3–5 | Ключевые показатели текущего и прошлого года = ячейки строк «Итого» (выручка, расходы Ozon, себестоимость, управленческий результат, маржа, оценка X, сводка состояний) |
| 6 | Полоса групп: продажи · себестоимость · комиссия · логистика · реклама · кабинет · финансовый результат · достоверность |
| 7 | Заголовки колонок; заметки — контракт (как в v1) |
| 8+ | Месяцы по годам (группа строк) и «Итого <год> · <период>» |

- Колонки «всего» групп и «Итого» года — суммы ПОКАЗАННЫХ ячеек (сходятся с калькулятором до копейки); маржа итога —
  по определению D3: Σ результат ÷ Σ (выручка + провизорная выручка X). Тождество строки:
  результат = выручка − себестоимость − расходы Ozon всего + компенсации − налог 2 % + оценка X.
- Подробные колонки (комиссия/эквайринг, 4 вида логистики, 4 вида рекламы, 3 вида расходов кабинета) свёрнуты в группы;
  показатели и итоговые колонки видны в свёрнутом виде.
- Состояния: известный дефект называется дефектом — «Требуется корректировка сторно D1», «Ошибка представления
  начисления M2»; без дефекта — «Неполные данные источника — нужна проверка». Пояснения прямо говорят, что выручка
  месяца есть.
- Деньги показываются в рублях без копеек (формат), значения ячеек — до копеек: «до копейки» сходятся значения ячеек,
  на экране сложение округлённых рублей может отличаться на 1–2 ₽.
- Подзаголовок содержит дату загрузки финансов Ozon: при новых данных прогон — WRITE с полной перераскладкой (раскрытые
  вручную группы снова сворачиваются); NOOP — при повторе без новых данных.
- Блок показателей стоит над колонками «Выручка», «Себестоимость», «Комиссия и эквайринг»… по порядку OWNER (выручка,
  расходы Ozon, себестоимость, результат, маржа) — подписи показателей в строке 3, а не заголовки колонок под ними.
- Закрепление 7 строк и колонки «Месяц»; условное форматирование результата (фон), маржи и «без X» (цвет текста),
  состояния месяца (цвет по смыслу).
- Идемпотентность: каждая запись снимает прежние правила УФ, объединения и группы (по `readSheetStructure`) в том же
  атомарном batchUpdate. `assertOwnTab` пропускает запросы раскладки только для sheetId вкладки и не даёт менять её
  название, индекс и видимость; запросы содержимого — по-прежнему общий `assertOnlyTab`.
- Перевод боевой вкладки: один прогон с `OZON_STORE_PNL_PUBLISH=1` и `OZON_STORE_PNL_MIGRATE_CONTRACT=<contractSha>`
  (без него — отказ `OZON_STORE_PNL_CONTRACT_MIGRATION_REQUIRED` до записи). Репетиция на тестовой книге: отказ без
  флага → миграция v1 → v2 (перечитывание PASS) → повторная запись раскладки поверх себя → NOOP.
