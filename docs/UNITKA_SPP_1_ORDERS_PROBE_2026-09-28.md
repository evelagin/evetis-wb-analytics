# СПП в Юнитку — этап 1: ценовые поля заказов WB

Дата: 28.09.2026. Задача: `AB` «СПП %» листа `WB_Юнит_2025` из факта WB.
Этот документ — отчёт живого пробоя API (этап 1.1) и план этапа 1. Книга, схема BigQuery и
Apps Script этим PR **не меняются**: изменение кода вступает в силу только после выкладки.

## 1. Живой пробой `GET statistics-api.wildberries.ru/api/v1/supplier/orders`

Токен — секрет `WB_TOKEN_STATISTICS` (категория «Статистика»; `WB_TOKEN_ANALYTICS` из Secret
Manager даёт 403 `scope is not allowed`). Два read-only запроса, `flag=0`, оба HTTP 200.

| запрос | строк | даты заказа |
|---|---|---|
| `dateFrom=2026-09-25` | 77 | 07.09 … 28.09 (фильтр API — по `lastChangeDate`) |
| `dateFrom=2026-06-25` | 1 897 | 08.06 … 28.09 |

**Поля.** В каждой строке 27 полей, из них ценовые: `totalPrice`, `discountPercent`, `spp`,
`finishedPrice`, `priceWithDisc`. Заполнены в 1 897 из 1 897 строк; `srid` уникален (1 897).

| поле | пустых | нулей | отрицательных | диапазон |
|---|---|---|---|---|
| `spp` | 0 | 265 | 0 | 0 … 45 |
| `discountPercent` | 0 | 0 | 0 | 58 … 65 (60 — в 1 883 строках) |
| `finishedPrice` | 0 | 0 | 0 | 277 … 883,02 |
| `priceWithDisc` | 0 | 0 | 0 | 499 … 1 294 |

**Тождества** (окно 25–28.09, 77 строк):
- `finishedPrice − priceWithDisc × (1 − spp/100)`: среднее +0,43 ₽, от −2,44 до +5,84 ₽,
  в пределах 1 ₽ — 59 из 77. Поле `spp` и фактическая скидка покупателя
  `1 − Σ finishedPrice / Σ priceWithDisc` совпадают до 0,3 п.п. за день.
- `priceWithDisc = totalPrice × (1 − discountPercent/100)` с точностью 0,4 ₽:
  `totalPrice` — цена до скидки продавца, `priceWithDisc` — цена продавца.

Для сравнения: в выкупах (`V_WB_SALES_RETURNS`, сентябрь) `finished_price` расходится с
`price_with_disc × (1 − spp/100)` на 10–24 ₽ в среднем по строке. На заказах этого нет.

**СПП по дате заказа** (взвешенная `1 − Σ finishedPrice / Σ priceWithDisc`):

| период | заказы | выкупы, по дате выкупа |
|---|---|---|
| 25.09 / 26.09 / 27.09 / 28.09 | 41,3 / 42,2 / 41,9 / 41,8 % | 36,5 / 40,3 / 39,2 / — % |
| сентябрь | 30,0 % | 12–40 % по дням |
| август | 10,0 % (35 % строк со `spp = 0`) | — |
| июль / июнь | 39,0 / 38,3 % | — |

СПП по заказам совпадает с витринной (40,9 % на 28.09) и известна в день заказа; по выкупам —
ниже и с задержкой.

**Глубина.** `dateFrom` фильтрует по `lastChangeDate`; надёжное окно бэкфилла — с 25.06
(≈ 90 дней). Для решения «заполнять с 01.09.2026» его достаточно.

## 2. Решения владельца (28.09.2026)

- `AB` заполняется автоматически **с 01.09.2026**; дни до 01.09 не трогаются.
- Будущие дни не заполняются: только закрытые дни (≤ LCD), по факту заказов своего дня.
- Снимки витрины (этап 4) не делаются.

## 3. Этап 1 — что меняется

`apps-script/ingestion/WbOrdersLoader.gs`: `ORDERS_RAW_HEADERS_` 29 → 33 колонки, в конец
добавлены `total_price`, `discount_percent`, `spp`, `finished_price` — сырые значения API.
Нет поля → пустая ячейка (NULL в BQ), `0` остаётся `0`.

Не меняются: первые 29 колонок и их значения, `row_hash` (цены в него не входят), дедуп-вью
`V_WB_ORDERS` (`SELECT *` — новые колонки проходят сами), `FACT_ORDERS`, колонка `Q`
(брутто-заказы), лист `RAW_WB_ORDERS` (legacy; в sheet-режиме новые `set()` — no-op).

Проверка на 1 897 строках живого ответа (Node, код ветки против `main`): первые 29 значений
и `row_hash` совпали у всех строк; 4 новых поля равны сырому API у всех строк; 265 нулевых
`spp` сохранены как `0`.

## 4. Выкладка — только после одобрения

1. Выложить `WbOrdersLoader.gs` в проект Apps Script.
2. Первый прогон загрузчика (`getRawOrdersSheet_` → `wbOrdersBqEnsureTable_`) аддитивно
   добавит в `wb_raw.RAW_WB_ORDERS` 4 колонки `STRING NULLABLE`. Проверить схему.
3. Бэкфилл: `importWbOrdersFromApi('2026-06-25', '<сегодня>')`. Приёмник append-only,
   дедуп — `V_WB_ORDERS` (last-wins: `last_change_date`, затем `loaded_at`).

**Контрольные цифры** (до / после, по `_order_date` 25.06 … сегодня):

| проверка | ожидание |
|---|---|
| `COUNT(*)` и `COUNT(DISTINCT srid)` в `V_WB_ORDERS` | не меняются |
| `SUM(price_with_disc)`, `COUNTIF(is_cancel)` по дням в `V_WB_ORDERS` | не меняются |
| `wb_mart.FACT_ORDERS` (Q, S) | не меняется |
| строки `V_WB_ORDERS` с непустым `spp`, заказы с 01.09 | 100 % |

Откат: вернуть прежний `WbOrdersLoader.gs`. Добавленные колонки остаются пустыми для новых
загрузок и ни на что не влияют (все потребители читают колонки по имени).
