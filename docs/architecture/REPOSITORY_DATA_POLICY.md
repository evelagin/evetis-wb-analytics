# Политика хранения данных репозитория EVETIS Analytics

**Редакция 1 · 2026-09-07**

Документ отвечает на один вопрос: *что кладём в Git, а что — нет*.
Он написан после разбора рабочего дерева, в котором накопилось 99 неучтённых
файлов и один production-файл, работавший в облаке, но отсутствовавший в Git.

---

## 1. Главный принцип

**Git хранит решения и код. Данные живут в BigQuery и GCS.**

Репозиторий — не озеро данных. Если файл можно пересобрать загрузчиком или
запросом, его место не здесь. Если файл фиксирует решение, доказательство или
поведение production — его место здесь.

---

## 2. Что хранится в Git

| Категория | Где | Пример |
| --- | --- | --- |
| Production-код загрузчиков | `cloud/src/**`, `pipelines/**` | `pipelines/ozon/runtime/entities.py` |
| Авторитетный DDL | `sql/**` | `sql/ozon/stage3_4d2_ozon_mart_forward.sql` |
| Скрипты отката | `sql/**` рядом с DDL | `sql/ozon/stage3_4d2_rollback.sql` |
| Инфраструктура | `infra/terraform/**` | `wb_prices_observer.tf` |
| CI/CD | `.github/workflows/**` | `deploy-prod.yml` |
| Тесты | рядом с кодом | `cloud/src/**/*.test.ts` |
| Архитектура и решения | `docs/**/*.md`, `ARCHITECTURE.md` | `PR2_PHASE_A_DISCOVERY.md` |
| Доказательства аудита | `docs/<домен>/audit_<дата>/<тема>/*.csv` | `audit_2026-09-06/tariffs/*.csv` |
| Первичные документы поставщика | `docs/ozon/audit_*/tariffs/source/*.xlsx` | официальные тарифные таблицы Ozon |
| Компактные справочники-исходники | `tools/**`, `sql/**` | генераторы с зашитой описью |
| Дашборды Metabase (описание) | `metabase/**` | `cards/*.json`, `manifest.json` |

**Правило для DDL.** Любой объект BigQuery, от которого зависит production,
должен иметь исходник в `sql/`. Проверяемо: SHA-256 развёрнутого тела совпадает
с исходником (см. `sql/pricing/pr2_ddl_verify.sql`).

**Канонический слой (R2A, 2026-09-18).** Исторические миграции (`sql/<домен>/stage*`, `pr_*`)
описывают переходы. Текущий контракт объекта production описывает `sql/current/<dataset>/`:
один файл на объект плюс `MANIFEST.json` (правила — `sql/current/README.md`). Идентичность и
дрейф текущих объектов сверяются с каноническим слоем, а не с миграциями. Сейчас покрыт
`ozon_mart`.

---

## 3. Что живёт в BigQuery

- сырьё маркетплейсов (`wb_raw`, `ozon_raw`);
- нормализованные витрины (`wb_mart`, `ozon_mart`);
- справочники (`evetis_ref`);
- журналы прогонов и OPS (`wb_ops`);
- любые повторяющиеся наблюдения (цены, тарифы, остатки, реклама).

**Авторитетные справочники — только здесь.** Если владелец ввёл данные вручную
(себестоимость, штрихкоды, РРЦ, соответствие SKU), их дом — `evetis_ref`, а не
книга Excel на одном ноутбуке.

---

## 4. Что живёт в GCS

- крупные выгрузки API, которые нужно сохранить как есть;
- архивы сырья аудитов;
- всё, что больше нескольких мегабайт и не является доказательством решения.

---

## 5. Что остаётся локально и не версионируется

| Что | Правило `.gitignore` | Почему |
| --- | --- | --- |
| Сгенерированные книги Excel | `docs/**/*.xlsx` | пересобираются; решение уже в `.md` рядом |
| Рабочая папка ассистента | `Claude outputs/` | не часть репозитория |
| Операционные ТЗ фулфилменту | `docs/tz_ozon_*/` | партнёрские документы, не аналитика |
| Юридические документы | `docs/legal/` | отдельный контур, решение владельца |
| Сырьё аудитов | `docs/ozon/audit_*/raw/**` | восстанавливается загрузчиками |
| Заготовки загрузки в BQ | `docs/ozon/audit_*/load/**` | промежуточный слой |
| Кэш Python | `__pycache__/`, `*.pyc` | артефакт запуска |
| Локальные настройки | `.claude/settings.local.json` | у каждой машины свои |
| Артефакты Playwright | `.playwright-mcp/` | артефакт теста |

Правило `.gitignore` **не удаляет** файл. Он остаётся на диске; репозиторий
просто перестаёт им управлять.

---

## 6. Что не коммитим никогда

- токены, ключи, пароли, cookies, service-account JSON;
- `.env` с реальными значениями;
- любые учётные данные WB, Ozon, GCP.

Секреты живут в Google Secret Manager. Код обращается к ним **по имени**:

```python
subprocess.check_output(["gcloud", "secrets", "versions", "access", "latest",
                         f"--secret={name}"])
```

Так уже написан `docs/ozon/audit_*/raw/backfill_v1/_bf_common.py` — это образец.

---

## 7. Исключения из ignore — только по маске

Перечисление файлов-исключений уже один раз стоило нам потери:
`_bf_sku_spend_boundary.py` (97 строк рабочего кода выгрузки Performance API)
молча выпадал из репозитория, потому что в списке исключений было пять имён,
а скриптов стало шесть.

**Правило:** исключение задаётся маской (`!.../backfill_v1/*.py`), а не списком.

---

## 8. Куда класть новый код из каталога аудита

Скрипт, написанный внутри `docs/**/audit_*/raw/`, — это код, а не сырьё.
Пока он одноразовый и привязан к аудиту, он может остаться там (маска его
сохранит). Как только его начинают запускать повторно, он переезжает:

| Тип | Куда |
| --- | --- |
| Переиспользуемый загрузчик | `pipelines/<домен>/runtime/` |
| Утилита разработчика | `tools/` |
| SQL | `sql/<домен>/` |

---

## 9. Именование

```
docs/<домен>/audit_<ГГГГ-ММ-ДД>/<тема>/<артефакт>.csv
docs/<домен>/STAGE_<этап>_<НАЗВАНИЕ>.md
sql/<домен>/<этап>_<объект>.sql
sql/<домен>/<этап>_rollback.sql
```

Дата в имени каталога аудита — дата *сбора данных*, не дата отчёта.

---

## 10. Проверка перед коммитом

```bash
git status --porcelain                # пусто, кроме намеренно игнорируемого
git ls-files | while read -r f; do git check-ignore -q --no-index "$f" \
  && echo "SHADOWED: $f"; done        # ни один versioned-файл не скрыт
```

Второй проверкой ловится самая опасная ошибка правил: широкий шаблон,
прячущий уже versioned production-файл.
