## 1. Что изменилось по существу

Было: 25 приёмочных SQL-артефактов, из них автоматически исполним **один**. Остальные
прогоняли руками один раз при сдаче этапа, после чего они переставали что-либо охранять.

Стало: **13 артефактов подключены**, 228 проверок (207 активных), исполняются одной командой,
дают машинный вердикт и код выхода. Прогон против production 2026-09-21 — все ворота PASS.

**Бизнес-логика не переписана ни в одном месте.** Вместо перевода проверок на новый язык
введены адаптеры, исполняющие существующие форматы:

| Адаптер | Формат | Что делает |
|---|---|---|
| `check_blocks` | `-- @check <ID>` + SELECT с колонкой `status` | исполняет как есть (SCALE 1) |
| `assert_script` | `ASSERT <выражение> AS '<имя>';` | исполняет **то же выражение** как `SELECT IF(…, 'PASS','FAIL')` |
| `verdict_select` | самостоятельные SELECT с колонкой-вердиктом | исполняет как есть |

Ключевая выгода `assert_script`: скрипт `ASSERT` падал на первом нарушении и не давал отчёта —
теперь виден каждый пункт по отдельности, с наблюдёнными значениями.

## 2. Найдено при первом же прогоне

Пять условий, которые раньше никто не исполнял, оказались красными. Каждое разобрано, ни одно
не отключено молча.

| Условие | Классификация | Доказательство |
|---|---|---|
| `T29` / `T40` Control Tower | **подтверждённый дефект** → UBR-001 | таблица контроля SKU показывает 208 карточек, Owner Home — 210; локализовано до двух карточек `EVT-SET-TON-CREAM-MOIST` (WB, 13.09 и 18.09) с `in_plan = FALSE` |
| `F-15`, `F-16` удержаний | `superseded` | сам автор артефакта пометил их замещёнными FIN CONTRACT V2 (шапка файла, 16.09) |
| `F-18` удержаний | `stale_snapshot` | фиксирует состав датасетов на 28.08 (4 / 41 / 56); сегодня 29 / 97 / 77 |

Исключение из ворот требует статуса, причины и доказательства — исключение без доказательства
роняет тесты, а исключение, ссылающееся на несуществующую проверку, роняет прогон.
Исключённая проверка продолжает исполняться, и её наблюдённый статус виден в отчёте.

## 5. Исполняемый путь целиком

```
изменение → tools/impact_analysis.py  (объекты, потребители, контракты, риск-тир)
          → tools/verify_task.py      (REPOSITORY · SQL_VALIDATION · GIT_PROD_PARITY ·
                                       DATA_CONTRACTS · PIPELINE_HEALTH · REGRESSION · UBR)
          → вердикт PASS / FAIL / BLOCKED, код выхода 0/1/2/3, JSON-артефакт
```

`BLOCKED` отделён от `FAIL` намеренно: отсутствие доказательства не выдаётся ни за успех, ни
за провал. Отсутствующая зависимость инструмента — тоже `BLOCKED`, иначе код обвинялся бы в
том, чего никто не проверял.

## 5a. Интеграционный прогон 2026-09-21

```
python tools/verify_task.py --full --project <PROJECT> --token-command "…" --task phase2-integration

FAIL           REPOSITORY          рабочее дерево было грязным во время прогона
PASS           SQL_VALIDATION
PASS           GIT_PROD_PARITY     14 из 14 MATCH
PASS           DATA_CONTRACTS      все 11 наборов-ворот
UNKNOWN        PIPELINE_HEALTH     проверок 7, включённых конвейеров без проверки 10 (CRITICAL — 2)
NOT_APPLICABLE REGRESSION          при --full все наборы уже в DATA_CONTRACTS
8              UNRESOLVED_BUSINESS_RULES

ВЕРДИКТ: FAIL
```

Прогон сделан до фиксации документов, поэтому `REPOSITORY` красный — и это ровно то поведение,
которое требовалось: незафиксированное дерево не считается завершённой задачей.

**Ворота нашли собственную регрессию.** На чистом дереве `REPOSITORY` остался красным из-за
теста `test_dataset_without_policy_fails_closed`: он копировал фикстуру в каталог `wb_mart`,
чтобы доказать отказ датасету без политики, — а Phase 2 дала `wb_mart` ревью-политику, и тест
молча перестал проверять то, ради чего написан. Исправлено, тестов стало 349.

**Итоговый прогон на чистом дереве:**

```
PASS           REPOSITORY
PASS           SQL_VALIDATION
PASS           GIT_PROD_PARITY
NOT_APPLICABLE DATA_CONTRACTS      ветка не трогает объектов данных
UNKNOWN        PIPELINE_HEALTH     10 включённых конвейеров без проверки, 2 из них CRITICAL
PASS           REGRESSION          пять критичных наборов, которых изменение не касалось
8              UNRESOLVED_BUSINESS_RULES

ВЕРДИКТ: BLOCKED
```

`BLOCKED`, а не `PASS`, — и это правильный ответ. Код ветки доказан, но здоровье платформы
доказать сегодня нельзя: `PIPELINE_HEALTH` даёт `UNKNOWN`, потому что молчание непокрытого
конвейера — неизвестность, а не здоровье. Направление станет зелёным после миграции
наблюдаемости, которая подготовлена и ждёт ACK.

## 6. Исправления в самих воротах

- Ключевое слово внутри строкового литерала больше не считается мутацией. Иначе read-only
  гейт отвергал именно те проверки, которые сторожат мутации (`routine_definition LIKE
  '%TRUNCATE%'`), — и `REPLACE()` как обычную строковую функцию.
- Маска комментариев сохраняет длину: схлопывание комментария в один пробел сдвигало
  смещения и резало SQL в произвольном месте.
- Ответ BigQuery с усечённой страницей теперь ошибка, а не тихо неполный результат.
