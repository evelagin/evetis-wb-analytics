# Autonomous Engineering v1 — эксплуатация

## 1. Как это работает в обычный день

1. `autonomy-watch` по расписанию (07:23 / 13:23 / 19:23 МСК) прогоняет ворота read-only и
   детектор здоровья. Модель не вызывается. Итог — в job summary; ветка `autonomy-state`
   хранит историю наблюдений.
2. Если все проверки HEALTHY или KNOWN — ничего больше не происходит, оповещений нет.
3. При устойчивом новом падении (два подряд) или деградации здоровья наблюдатель создаёт
   конверт инцидента и цель инженера (обе валидируются по схемам) и, **только при
   `AE_ENABLED=true`**, диспатчит `autonomy-run`.
4. `autonomy-run` проходит роли по отдельным машинам. Итог — в job summary и в issue с меткой
   `autonomy`; при READY_FOR_PR — draft PR из ветки `ae/…`.
5. Владелец читает draft PR, запускает CI (события `GITHUB_TOKEN` его не запускают — V2
   backlog п. 1) и решает: слить, доработать или закрыть.

## 2. Когда владелец получает оповещение

Только при: новом инциденте; WAITING_FOR_HUMAN (нужен ACK плана или решение); READY_FOR_PR;
BLOCKED после автономных попыток; FAILED/infra_failure; FLAPPING и INFRA_BLOCKED наблюдателя.
Для HEALTHY оповещений нет. Оповещение — одно на смену класса, а не на каждый прогон.

## 3. Состав отчёта прогона

Цель/инцидент; первопричина (если доказана); изменённые файлы; доказательства ворот
(вычислены системой, не агентом); вердикты ревьюера и гейткипера с причинами;
**production-мутаций — 0** (обязано); остающаяся неопределённость; PR; что нужно от владельца.
Генерирует `tools/autonomy/report.py`.

## 4. Модель стоимости

| Статья | Когда тратится | Оценка |
|---|---|---|
| Actions-минуты наблюдателя | 3 раза в сутки, ~5–10 мин | ~15–30 мин/сутки, модель — 0 |
| BigQuery наблюдателя | 13 наборов read-only | порядка единиц ГБ/сутки (набор `wb_executive_v2` — ~4,7 ГБ за прогон) |
| Прогон AE | только по устойчивому инциденту | 9 job'ов × 2–15 мин; модель — до $15 на вызов инженера и $5 на вызов ревьюера по `policy.json` |
| Худший случай одного прогона | 3 итерации × (план+реализация) + 3 ревью | потолок ≈ 3 × $15 + 3 × $5 = $60, плюс проходы ≤ 8 |

Здоровая система модель не вызывает, поэтому переменная часть расходов равна нулю, пока
нет инцидентов. Фактическая стоимость каждого вызова записывается в `run.usage`
(`total_cost_usd`, `num_turns`, `duration_ms` от рантайма) и выводится в отчёте.

## 5. Лимиты и отмена

- Выключатель: переменная репозитория `AE_ENABLED`. Не `true` → наблюдатель только наблюдает,
  `autonomy-run` не начинается.
- Отмена активного прогона: `gh run cancel <id>`; состояние останется в последнем записанном
  шаге, `next_pass` вернёт `infra_failure`, повторного запуска не будет.
- Параллелизм: группа `autonomy-run`, один активный прогон; ключ дедупликации — один прогон
  на инцидент.

## 6. Восстановление после сбоя

Состояние — ветка `autonomy-state`, а не память модели. Любой job можно перезапустить с
`run_id`: доверенный шаг прочитает запись прогона и продолжит с последнего записанного
состояния (`test_F_restart_recovers_from_durable_state_without_memory`). Упавший job не
зацикливает систему: `next_pass` диспатчит повтор только из FIXING и не более 8 проходов.
