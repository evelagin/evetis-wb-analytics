## 4. Семантика расчёта WB — доказанное тождество

Главный результат Phase A. На **38 698 строках продаж** проверено:

```
for_pay = retail_price_withdisc_rub × (1 − commission_percent/100) − acquiring_fee
```

**Совпадение с точностью ±0,02 ₽ на 97,2 % строк.**

Примеры (реальные строки `EVT-HC-HAND-300`):

| `rp_withdisc` | `commission_%` | `acquiring` | расчёт | факт `for_pay` |
|---|---|---|---|---|
| 470 | 32,5 | 9,68 | 307,57 | **307,57** |
| 650 | 41,5 | 16,12 | 364,13 | **364,13** |
| 650 | 41,5 | 19,62 | 360,63 | **360,63** |
| 650 | 41,5 | 14,68 | 365,57 | **365,57** |

### Что из этого следует (§24)

| Вопрос | Ответ |
|---|---|
| От какой цены считается **комиссия** | `retail_price_withdisc_rub` — цена **продавца** после его скидки |
| От какой цены считается **выплата** | та же цена продавца |
| Что платит **покупатель** | `retail_amount` = цена продавца × (1 − СПП) |
| Уменьшает ли СПП выплату продавцу | **НЕТ.** СПП полностью финансирует WB |

Проверка на строке: `rp_withdisc` 650, `spp_percent` 38 → `retail_amount` = 403 = 650 × 0,62 ✓,
при этом `for_pay` = 364,13 рассчитан от 650, а не от 403.

**Это ключевой факт всего PR-2.** Экономика продавца определяется именно той ценой,
которую наблюдает PR-1. Отсутствие pre-sale СПП, зафиксированное в PR-0/PR-1,
**не мешает** считать форвардную экономику продавца — оно мешает только
рассуждать о цене покупателя.

`acquiring_fee` ≈ **1,625 %** от цены продавца в среднем (переменная per-sale).

## 7. Возвраты — измеримая нагрузка, а не гипотеза

За 90 суток в детализации:

| Операция | Строк | Сумма |
|---|---|---|
| Продажа | 2 732 | `for_pay` 1 277 883 ₽ |
| **Логистика** | **3 148** | 182 421 ₽ |
| Возмещение издержек по перевозке | 7 385 | — |
| Хранение | 139 | — |
| Компенсация скидки по программе лояльности | 59 | — |

**Событий логистики на 15,2 % больше, чем продаж** (3148 / 2732 = 1,152).

Это и есть эмпирическая нагрузка возвратов и отмен: логистика начисляется
на заказ, а не на выкуп. Модель не требует угадывать «вероятность возврата ×
стоимость возврата» — множитель измеряется напрямую:

```
expected_logistics_per_sale = logistics_amount_total / sales_count
```

За 90 суток: 182 421 / 2 732 = **66,77 ₽ на проданную единицу**,
против 57,95 ₽ на событие логистики. Разница — и есть цена невыкупа.

**[НЕ РЕШЕНО]** Разделение отмены до доставки / возврата после доставки /
логистического возврата (§11) требует связки по `srid` между заказами,
продажами и детализацией. Технически возможно, в Phase A не выполнено.

## 11. Предлагаемая форвардная формула

Выводится из доказанного тождества §4, а не из общего шаблона.

```
seller_effective_price       P                     (наблюдается PR-1)
commission_rub               = P × commission_pct/100
acquiring_rub                = P × acquiring_pct/100          (≈1,625 %)
expected_logistics_rub       = E[logistics | SKU]             (включает нагрузку невыкупа)
cogs_rub                     = COGS(SKU, date)

contribution_before_ads      = P − commission_rub − acquiring_rub
                               − expected_logistics_rub − cogs_rub

contribution_after_ads(drr)  = contribution_before_ads − P × drr

break_even_before_ads:  решить contribution_before_ads(P) = 0
  ⇒ P* = (expected_logistics + COGS) / (1 − commission_pct/100 − acquiring_pct/100)

break_even_with_ads(drr):
  ⇒ P* = (expected_logistics + COGS) / (1 − commission_pct/100 − acquiring_pct/100 − drr)

target_price(c):  требуемый вклад c ₽ на единицу
  ⇒ P* = (expected_logistics + COGS + c) / (1 − commission_pct/100 − acquiring_pct/100)

max_affordable_drr(P) = contribution_before_ads(P) / P
```

Свойства формулы, пригодные как инварианты для тестов (§56):
рост COGS, комиссии, логистики или требуемого вклада **повышает** `P*`;
добавление рекламной нагрузки **повышает** `P*`. Знаменатель обязан быть > 0 —
иначе SKU нерентабелен при любой цене и должен возвращать `BLOCKED`, а не бесконечность.

**Не входит намеренно:** налог, хранение, приёмка, штрафы, удержания уровня кабинета,
фулфилмент, OPEX. Каждое исключение должно быть видно в выходном объекте.

## 16. Рекомендация

**GO WITH LIMITATIONS.**

Обосновано:
- учётные данные готовы, новый токен не нужен;
- формула расчёта WB доказана на 38 698 строках;
- база выручки установлена однозначно — цена продавца;
- COGS покрывает 23/25, два пропуска честно уйдут в `BLOCKED`;
- комиссия и логистика моделируемы.

Ограничения, которые войдут в результат как явные, а не как замалчивание:
1. форвардная логистика РФ **недоступна** через API — только эмпирическая оценка с диапазоном;
2. семантика комиссии не разрешена на 0,25–0,75 п.п. — до Phase D `confidence = MEDIUM`;
