## 1. Закрытие blocker'а аудитора

**Замечание.** После перехода на per-metric baseline общие `baseline_sample_clicks`
и `baseline_pair_count` остались SKU_EX_SELF-only (`x_clicks`, `x_pair_count`) и потому
семантически неверны на строках со `STORE_EX_SELF` / смешанным baseline. Плюс
`baseline_fallback_reason` был объявлен в ред. 2, но не реализован.

**Сделано.**

1. Переименование (потребителей не было, миграция не нужна):

```
baseline_sample_clicks  →  sku_ex_self_sample_clicks
baseline_pair_count     →  sku_ex_self_pair_count
```

Имя теперь говорит, для какого варианта baseline величина существует. Проверено
статическим аудитом: старых имён в файле **0**, новые встречаются 2 и 3 раза
(объявление в двух оконных вью + проброс в `V_ADS_FUNNEL_SIGNALS`).

2. `baseline_fallback_reason` реализован по классам утверждений и включён в контракт:

```
NULL                                       все шесть классов сравниваются со своим SKU
'CPC:SKU_SAMPLE_TOO_SMALL'                 класс откатился на магазин
'ORDER_CARTS:NO_BASELINE'                  baseline недоступен ни на одном уровне
несколько причин                           через запятую, в алфавитном порядке
```

Фактическое распределение на 90d (1 432 строки):

```
baseline_level = 'SKU_EX_SELF' (все классы на своём SKU)   1 111 строк
baseline_level смешанный (SKU_EX_SELF,STORE_EX_SELF)         286
baseline_level = 'STORE_EX_SELF' (все классы на магазине)     35
baseline_level = 'NONE'                                        0
baseline_fallback_reason IS NULL                           1 111   ← ровно совпадает
строк с '…:SKU_SAMPLE_TOO_SMALL'                             321   = 286 + 35
строк с '…:NO_BASELINE'                                        0
```

Согласованность проверена гейтом: строк с `baseline_level='SKU_EX_SELF'` и непустой
причиной — **0**; строк с не-SKU уровнем и пустой причиной — **0**.

3. **K9 стал постоянным гейтом** — внесён в дизайн как §12.5, прогоняется при каждом
выкате Ads-4, а не только при первом.

Дизайн обновлён до **ред. 3**: §7.1 (переименование + контракт `baseline_fallback_reason`),
§12.4 K5 (сверка по `baseline_cpc_level` + две проверки согласованности причины),
§12.5 (K9). Архитектура не изменена.

## 4. K9 — постоянный гейт

**K9a. Оконные вью различаются только константами окна.**

```
V_ADS_FUNNEL_QUERY_28D  нормализованный sha256 = 85ef85c42ed78acc3c10…
V_ADS_FUNNEL_QUERY_90D  нормализованный sha256 = 85ef85c42ed78acc3c10…   идентичны ✅
```

**K9b. Файл репозитория идентичен выкаченному объекту — по всем пяти вью.**

```
V_ADS_FUNNEL_QUERY_DAILY   файл 6335e873929ca0a4… = BigQuery ✅
V_ADS_FUNNEL_QUERY_28D     файл e8c32bc025a5aa40… = BigQuery ✅
V_ADS_FUNNEL_QUERY_90D     файл c3b83d5b16fa9bdf… = BigQuery ✅
V_ADS_FUNNEL_SKU_28D       файл 008cca3b97039775… = BigQuery ✅
V_ADS_FUNNEL_SIGNALS       файл 3b70e54d3f64bcfe… = BigQuery ✅
```

🔴 K9b ловила расхождение **дважды**, и оба раза причина одна — SQL выкатывался набранным
вручную, а не из файла:

* прогон 1, `V_ADS_FUNNEL_QUERY_28D/90D`: пять пустых строк и один пробел;
* прогон 2, `V_ADS_FUNNEL_SKU_28D`: вью логически не менялась, поэтому её не
  перевыкатывали — и осталось исходное расхождение от первого выката.

Оба раза смысловая разница нулевая. Ровно поэтому гейт и нужен: такие расхождения
не видны глазом и не ловятся ни одним содержательным тестом.

**Прогон 3 (синхронизация документации перед merge).** По замечаниям аудитора к PR #99
исправлены три текста: шапка `ads4_funnel_v1.sql` переключена с «ред. 2» на «ред. 3»,
в design §7.1 запасной уровень baseline назван `STORE_EX_SELF` (а не `STORE` —
он тоже исключает саму пару), в design §12.2 строка G8 переписана на
`sku_ex_self_sample_clicks = sku_clicks_total − clicks_sum` при
`baseline_cpc_level='SKU_EX_SELF'`.

🔴 Правка шапки SQL затрагивает **только комментарий**, поэтому тела вью не изменились
и перевыкат не требуется. Проверено K9b: SHA-256 всех пяти тел после правки совпадают
с выкаченными `view_definition` (`6335e873…`, `e8c32bc0…`, `c3b83d5b…`, `008cca3b…`,
`3b70e54d…`) — те же значения, что и до правки. Код не трогался.
